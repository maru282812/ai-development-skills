# アプリ・管理画面の基準（媒体: app）

作成: 2026-11-02 / 棚卸し: [../references/design-inventory-2026-11-02.md](../references/design-inventory-2026-11-02.md)

対象: 業務の管理画面・現場の端末・顧客向けのスマホ画面（LIFF 含む）・会員アプリ。集客サイト・LP は対象外（サイト媒体は [README.md](README.md) を参照）。

## 0. この文書の位置づけ

- **優先順位**: プロジェクト内のデザインシステム（`design.md`・`tokens.css`・`globals.css` の token ブロック等）＞ この文書 ＞ hallmark の一般則。
- この文書が持つのは**構造と振る舞いの規則**（色の役割・骨格・状態・行操作・文言・合格基準）。**ブランドの色と書体の値は持たない**。値はプロジェクトかブランドから取る。何も無ければ hallmark の `references/polish/tokens.md`（中立ランプ）を起点にする。
- 日本語の組版（書体・字間・行送り・句読点）は hallmark の `references/ja.md` に従う。ここでは繰り返さない。
- 各規則の末尾の【】は出どころ。実際に事故や差し戻しがあって決まったものなので、外すときは理由を残す。

## 1. 画面の種類で密度を決める

最初に、この画面がどれかを決める。混ぜない。

| 種類 | 例 | 基準の幅 | 本文 | タップ／部品の高さ | 密度 |
|---|---|---|---|---|---|
| **業務の管理画面（PC）** | リード管理・予約表・台帳 | 1280 | 14px | 部品 32px（md 以上）、スマホでは 36px を残す | 詰める。1280 幅で「見出し＋絞り込み＋表の最初の10行前後」が1画面に入る【website-sales-ai】 |
| **業務の管理画面（PC＋スマホ兼用）** | 社内の司令塔・オーナー用の管理画面を外出先でも開く | 1280 と 390 の両方 | PC 14px、スマホ幅でも 14px（説明文を 12px に落とさない） | PC 32px。スマホ幅では最低 36px、行のリンク・主要操作・ラジオ等の選択肢は**行全体・ラベル全体を押せる形で 44px** | PC は管理画面どおり詰める。スマホ幅では1列にし、1行の情報量を減らす（補足は折りたたむ）【shiseki_ai 実地確認 2026-11-02】 |
| **現場の端末** | 店頭・厨房・受付のタブレット、片手操作 | 768〜1024 | 16px 以上 | 56px 以上 | 粗く。一目で状態が読めること優先、コントラスト強め【qr-order】 |
| **顧客向けスマホ** | LIFF・予約・問診 | 375 | 16px | 44px 以上 | 1画面1決定。PC では中央 600px 前後の1カラム【PET】 |
| **会員アプリ** | 学習・日記などの継続利用 | 375 | 16px | 44px 以上 | 下部タブ5個まで。公開側（LP）とはナビを分ける【nikki_world】 |

- 入力欄の文字は全種類で 16px 以上（iOS の自動ズーム防止）。
- **12px 以下はメタ情報（日時・件数・ID・補足の注記）だけ**。説明文・行の本文・状態の理由文は本文サイズで組む。画面の文字数のうち 12px 以下が 3 割を超えたら、説明文まで縮んでいる疑いが強い（要素数で数えると日時・件数・バッジのような短い部品で比率が膨らむので、文字数で比べる）【shiseki_ai 実地確認 2026-11-02：直す前は要素の 8 割が 12px だった】。
- 兼用の画面は、どちらの幅を正にするかを design.md に1行書いておく（PC の密度に寄せるとスマホで押せず、スマホに寄せると PC で間延びする）。
- 横スクロールは表とカレンダーだけ、専用のラッパーの中で許可する。画面全体を横にはみ出させない【PET・website-sales-ai】。

## 2. 色は「意味」とだけ結ぶ

1. **色と意味は一対一**。主色＝進行・選択・主ボタン・リンク、注意色＝要対応・未処理、緑＝完了・正常、赤＝削除・エラー。飾りのための色を足さない【PET §1・website-sales-ai】。
2. **注意色（琥珀・橙・黄）は1画面1系統まで**。違う種類の「要対応」が同じ画面に出るなら上下に離し、隣に置かない【PET】。
3. **状態は「色＋記号＋文言」の三重で示す**。色だけで状態を伝えない（色覚差・モノクロ印刷・遠目）【shiseki_ai・website-sales-ai】。
4. **状態の区分が多い業務**では、区分ごとに固定の色を `{色, 淡色}` の対で token にする（例: 重大・注意・進行中・確認待ち・顧客待ち・完了・保留）。画面ごとに色を選び直さない【shiseki_ai】。
5. **識別用の色（アバター等）と状態色を混ぜない**。名前で区別するだけの色は専用パレット8色程度を用意し、表示名のハッシュで選ぶ（連番や作成順で決めない）【PET §2】。
6. **白地に黄色系の文字は不可**（1.78:1 など基準未満になる）。注意色の文字には濃い専用 token を用意する【website-sales-ai】。
7. **フォーカスリングは 3:1 以上**。半透明で描く部品は、主色より一段濃い色を ring に当てる【website-sales-ai】。
8. **面は中立色**。背景・カード・罫・文字は無彩に近い1本のランプから取る。階層はグレーの塗り分けでなく、罫・余白・文字の太さと大きさで作る【website-sales-ai DON'Ts・unslop】。
9. **token を `:root` で定義するファイルは1つだけ**。複数の CSS が同じ名前を別の値で定義すると、読み込み順でページごとに色や角丸が変わる【PET §1-4】。
10. **部品・画面に生の色値を書かない**（`#xxxxxx`・`oklch(...)`・`bg-sky-500` のような色名クラス）。洗い出し:
    `grep -rnoE "(bg|text|border|from|to|via|ring)-(sky|emerald|amber|red|blue|green|yellow|orange|rose|slate|gray|violet|purple|indigo|teal|cyan)-[0-9]+" app features components --include=*.tsx`【website-sales-ai】

## 3. 書体と数字

- 和文 Web フォントを指定したら**必ず読み込む**。開発機に入っているせいで気づかず、他の端末で system-ui に落ちていた事故がある【PET §1-6】。`button` `input` `select` `textarea` は `font: inherit`。
- 件数・金額・点数・日付は `font-variant-numeric: tabular-nums`。表の数字の列は右寄せ【website-sales-ai】。
- ID・コード・差分は等幅【PET】。
- 見出しに斜体を使わない。

## 4. ページの骨格

管理画面のページは1つの形に固定する。分裂すると戻り導線のないページや実質3階層の画面が生まれる【PET §5.1：骨格が7系統に分裂していた】。

```
上部ナビ（またはサイドバー）… 全ページ共通。ページ側で書き換えない
ページ見出しの帯           … 必ず1つ。この順で以下だけ:
  ├ 戻る    … 親へ戻る1本のリンク（2階層目以降は必須）
  ├ h1      … 全ページ必須
  ├ 説明    … 1行（任意）
  └ 主ボタン … 1つまで
同じグループの兄弟タブ      … 2階層目
本文                       … 絞り込み・検索・並び替えは「表の直上」に置く（見出しの帯に混ぜない）
```

- **3階層を作らない**。戻り先は常に1つなので、パンくずは使わない【PET】。
- **主ボタンは1画面に1つ**。副操作は輪郭ボタンかリンクに格下げ【PET・website-sales-ai】。
- **頻度＝深さ**。毎日使う画面は1クリック、月1回の設定は2階層目。主目的はサイドバーから3クリック以内【PET・website-sales-ai】。
- **着地ページは「次にやること」から始める**。メニューの羅列や数字の羅列で始めない【PET P1】。
- トップのナビは 7±2 グループ。どの機能もどこかのグループに必ず属す【PET §3】。
- sticky は1画面に「見出しの帯」と「表のヘッダー」の2枚まで。z-index は token で持ち、生の数値を書かない【PET】。
- 版面は全幅・左寄せで全ページ揃える。フォームのカードだけ左寄せのまま `max-width`（860px 目安）を掛けてよい【PET】。
- スマホでは横ナビを下部タブ5個（最後は「その他」）に畳む【PET §6】。

## 5. 一覧と行の操作

**並び順を固定する**（副操作の数が変わっても両端が動かない）【PET §5.2】:

```
[↑][↓] … [編集] … [複製][プレビュー等] … [削除]
```

- 並び替えは左端、削除は右端に隔離。副操作が3つ以上なら右端の「…」メニューに畳む。
- ラベルは文字が既定。アイコンだけのボタンには `aria-label`、アイコン自体は `aria-hidden`。HTML エンティティの絵文字（✎ 🗑 等）は環境で見た目が変わるので禁止。
- **語彙を固定する**: 編集／複製／削除。「変更する」は保存ボタン用なので行操作に使わない。論理削除は「非表示にする」「非公開にする」と言い分ける。
- **破壊操作には確認を出し、確認文に影響の範囲を数字で書く**（「このタグを削除します。3頭に付いているタグも外れます」）。複製・プレビューなど無害な操作には確認を出さない。取り消せる通知で代えてもよい【PET・website-sales-ai】。
- 50件を超える一覧はページ送りか仮想化【website-sales-ai】。
- 長い値は `truncate` か折り返し、列見出しが1文字ずつ折り返さないこと。スマホでは表を表の中で横スクロールさせるか、「項目名：値」の縦並びのカードに変える【website-sales-ai】。
- リンクは `<a>`、操作は `<button>`。`div` に `onClick` を付けない【website-sales-ai】。

## 6. 空・読込・エラーの3状態

一覧を持つ画面は**3つとも必須**。画面ごとに独自の「読み込み中…」「データがありません」を書かず、共通部品にする【website-sales-ai §2・PET `state`】。

| 状態 | 中身 |
|---|---|
| 空 | 何が無いか／なぜ無いか・どこから作れるか／次の一手のボタン。絞り込みで0件なら「条件に合う○○はありません」＋条件を外すボタン |
| 読込 | 中身と同じ形の skeleton（表・一覧・カード・詳細）。表示がガタつかないこと |
| エラー | 何が起きたか／どうすればよいか／再試行。サーバーの原因文は小さく添えるだけ |

- 一覧の読込失敗を「0件」に化けさせない。操作（保存・削除）の失敗とは分けて出す。

**エラー文の型**【website-sales-ai（GOV.UK の日本語化）・PET】:
1. 何が起きたかを具体的に（「リード一覧を読み込めませんでした」「CSV の3行目に電話番号がありません」）。
2. どうすればよいかを書く。
3. 「エラーが発生しました」だけで終わらせない。英語の原因文を主文にしない。
4. 利用者を責めない（「不正な入力です」→「電話番号は数字とハイフンで入力してください」）。
5. 入力のエラーはその欄の近くに、どの欄かを文に入れて出す。
6. 設定の不備は、見る人（顧客・現場）の言葉に言い換える（「診療科目IDが不正です」を画面に出さない）。

## 7. フォーム

- **1節＝1カード**（見出し＋1行の説明）、**1設定＝1行**（左にラベル、右に入力、説明は入力の直下）。数値＋単位は1組、2〜3択はラジオかセグメント。親の選択で意味を持つ項目は連動して出す【PET `sf`：ラベルと入力が揃わず読めなかった】。
- ラベルの無い入力を置かない。プレースホルダをラベル代わりにしない【website-sales-ai】。
- 貼り付けを禁止しない（パスワード・確認欄も）【website-sales-ai】。
- 顧客向けは1画面1決定、選択肢は 3±1 ＋「その他」。既定値は前回の選択を入れ、「変更」を常に併記する【PET P3・P5】。

---

## 8. ダッシュボード・「今日」画面

- 数字の羅列でなく「**いまやること**」を、人単位・行動ボタン1つで出す【PET P1】。
- チャートには序列を付ける。主役の1枚を大きく、他は小さく種類を変える（順位リスト・短い表）。同じ大きさのチャートを並べない【unslop】。
- 1つのチャートに強調色は1つ。比べるものは中立色の段階で【unslop】。
- 数字のカードは「ラベル・大きい数字・比較先つきの変化（前月比 +12%）」だけ。スパークラインや飾りのアイコンで埋めない【unslop】。

## 9. 使わない見た目

| 使わない | 代わりに |
|---|---|
| 多色グラデーション・光る影・グラデ文字 | 単色の面＋罫。色は意味にだけ |
| 影で階層を作る（入れ子・大きい影） | 1px の罫で分け、影は最小限 |
| グレーの塗り分けで階層 | 地は1色、強弱は文字の太さと大きさ |
| 絵文字カード（🚀✨💡 の格子） | 線アイコンを必要な所だけ |
| 左ボーダーの色帯カード（`border-l-4`） | 状態はバッジか文字、枠は全周 1px |
| 注意色を飾りに使う | 主操作は主色、注意色は要対応だけ |
| `transition-all`・幅や高さのアニメーション | `transform` と `opacity` だけ。`prefers-reduced-motion` を尊重 |

出どころ: website-sales-ai DON'Ts・Vercel Web Interface Guidelines・unslop。AIっぽさ全般は hallmark の `references/polish/signs.md`。

## 10. 合格基準（アプリ版ゲート）

新しい画面を作るとき・大きく変えるときは、PR にこの表を貼る【website-sales-ai §4 を媒体共通に拡張】。

| # | 項目 | 合格の条件 | 確かめ方 |
|---|---|---|---|
| 1 | 密度 | §1 の種類どおり（管理画面なら 1280 幅で見出し＋絞り込み＋表10行前後） | 基準幅のスクショ |
| 2 | 3状態 | 一覧ごとに空・読込・エラーが共通部品で出て、エラーから再試行で戻れる | Playwright の `page.route` で API を止める／空にする／遅らせて撮る |
| 3 | フォーカス | Tab で全操作に届き、`:focus-visible` のリングが即時に見える（3:1 以上） | キーボードで一巡 |
| 4 | はみ出し | スマホ幅（375 か 390）で画面全体が横にはみ出さない。数字の列は右寄せ＋tabular-nums | `scrollWidth <= clientWidth`、スクショ |
| 5 | 到達 | 主目的がナビから3クリック以内。主ボタンは1画面1つ | 手で数えて PR に書く |
| 6 | 色の意味 | 生の色値がない。状態が色＋記号＋文言で示されている | §2-10 の grep、目視 |
| 7 | 文言 | エラー文が §6 の型（内部コード・英語の原因文が主文に出ていない）。行操作の語彙が §5 どおり | 目視 |
| 8 | 文字の大きさ | 12px 以下の文字が文字数で 3 割以下で、説明文・理由文に使われていない（§1） | `measure-app` の `smallTextRatio` と一覧 |
| 9 | 押せる範囲 | スマホ幅で、押せる要素が §1 の種類の基準（36px / 44px）以上。小さい物は行全体・ラベル全体を押せる形にしてある | `measure-app` の `smallTaps` |

あわせて: typecheck / test / build 緑、console に Uncaught なし。

### 自動計測 `measure-app`

項目 3・4・8・9 と AIっぽさの数値（グラデーション・大きい影・絵文字・大文字ラベル・斜体・負の字間・「！」）は自動で測れる。サーバーを起動した状態で、対象プロジェクトのフォルダから:

```
node C:/work/ai-development-skills/design/scripts/measure-app.mjs --base http://127.0.0.1:<port> --path / --out <出力先> [--login <ログイン手順.mjs>] [--tap 44]
```

- 出力: 幅ごとのスクリーンショット（初画面・全体）、`<幅>.json`（計測値）、`summary.md`（合格基準 3・4・8・9 の判定と AIっぽさの数値）。
- `--login` には `export default async (page, base) => { … }` の形のファイルを渡す（プロジェクトごとにログイン手順が違うため）。
- Git Bash から `--path` を渡すときは `MSYS_NO_PATHCONV=1` を前に付ける（`/` が Windows のパスに書き換えられるため）。開発用サーバーの表示（Next.js の N ボタン等）は計測から除外している。
- 幅は既定で 390・320・1280。`--widths 375,1024` で変えられる。
- 項目 1・2・5・6・7 は人が見る（2 は `page.route` で API を止めて撮る、6 は §2-10 の grep）。
