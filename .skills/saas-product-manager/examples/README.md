# examples

saas-product-manager の使用例。実際の整理結果は `<機能名>.md` でこのディレクトリに追加する。

## 例1: 顧客アンケート機能の仕様整理

### 入力例

> 顧客にアンケートを送って回答を集計したい。SaaSとして考えて、MVPに分けて、管理画面の仕様も考えて。

### Skill が見る観点

- ユーザー種別: テナント管理者(アンケート作成)/ エンドユーザー(回答)/ 運営
- 回答者はログイン必須か、URLを知っていれば回答できるか → 権限・RLS設計に直結するので最初に確認
- 漏れがちな機能: 回答の CSV export(ほぼ必須要望)、回答受付の締切・停止、未回答者への再通知
- MVP判断: 集計グラフは Phase 2 でよい(一覧 + export で代替可能)が、テナント分離は MVP で必須
- プラン影響: アンケート作成数の上限をプランで縛るか

### 出力例(短縮版)

```md
# 仕様整理: 顧客アンケート

## 目的
テナント管理者が顧客の声を構造化して収集し、サービス改善に使えるようにする。

## ユーザー種別
| 種別 | 役割 |
|---|---|
| テナント管理者 | アンケート作成・配布・結果閲覧 |
| 回答者 | 回答(ログイン不要、トークン付きURL) |
| 運営 | テナント横断の利用状況確認 |

## MVP範囲
- 含む: アンケート作成(テキスト/単一選択)、URL発行、回答、回答一覧、CSV export
- 含まない: 集計グラフ(一覧+CSVで代替)、再通知(手動でしのげる)、条件分岐設問

## Phase分け
| Phase | 内容 | 可能になること |
|---|---|---|
| 1 (MVP) | 作成・回答・一覧・export | アンケートを1本回せる |
| 2 | 集計グラフ・締切設定 | 結果確認が楽になる |
| 3 | 再通知・回答必須化 | 回収率が上がる |

## 権限設計
| 操作 | 回答者 | テナント管理者 | 運営 |
|---|---|---|---|
| 回答 | ○(トークンURL) | ○ | × |
| 結果閲覧 | × | 自テナントのみ | 全テナント(監査ログ必須) |

## 運用上の注意
- 回答に個人情報が入りうる → export 操作は監査ログ対象
- 匿名回答の扱い(IPも保存しない等)を利用規約と整合させる
```
