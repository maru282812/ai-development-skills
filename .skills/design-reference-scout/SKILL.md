# Purpose

**「なぜこのデザインなのか」を言えるようにする。**

このスキルが解く問題は1つ。**「AIで綺麗に配置して作りました」は売れない。**
提案の価値は成果物でなく **選定理由** にある。
根拠のない3案は3案ではなく、1案の揺らぎにすぎない。

型の本体（背景・ギャップ分析込み）:
`c:\work\ai-ideas\idea-engine\reference\design-methods\d07-three-axis-reference-proposal.md`

# 絶対ルール

1. **実際に検索する。1ページで終わらせない。**
   ギャラリーは **複数ページ × 複数軸**（業種／色／テイスト）で引く。
   「1カテゴリを1回開いて候補リストを得た」は探索ではない。
2. **実ページを開いていないサイトを参照として書かない。**
   ギャラリーのサムネイル・まとめ記事の一言評だけで「参照した」と書くのは違反。
   WebFetch で開いて確認した日を記録する。
3. **機能で候補を絞らない。**
   借りたいのは**見た目**（色/余白/写真/タイポ/動き）。
   「予約機能が無い」「ECだから」で候補を捨てると探索範囲が不当に狭まる。
   機能が効くのは**骨格を借りるときだけ**で、その対処は「除外」でなく「骨格は自前設計」。
4. **3案を軸で選ぶ。①③を当て馬にしない。**
   3案とも同じだけ本気で作る。当て馬は客に見抜かれ、提案全体の信頼が落ちる。
5. **構成とデザインを混ぜて提示しない。**
   客の「A案が好き」が骨格の話か色の話か区別できない状態にしない。
6. **参照を平均化しない。** 1案につき参照は2〜4件。多いほど凡庸になる。
7. **数値は観測値であって規範ではない。** 参照先のフォントサイズ・色比率は
   「そのサイトの選択」であり、自案件で測り直す前提で書く。

# When To Use

- 既存サイトを「作り直すとしたらどうするか」提案したい
- 新規LP・サイトの**方向性**をこれから決める
- 客に複数案を見せて選んでもらう必要がある
- 参考サイトを探すところから始まる

使わない場面:

- 方向が既に決まっている改修（3案が逆に混乱を生む）
- コンテンツ（写真・実績・料金）が未確定 → 先に揃える。見た目3案を出しても選べない
- 単一コンポーネントの修正 → [[design-variant-preview]]
- プロジェクト実物のトークン上で見た目を並べる → [[design-variant-preview]]
- 必要画面の洗い出し → [[screen-design-architect]]

# Procedure

## 1. 前提の確認（ここで止まることがある）

着手前に確認する:

- **コンテンツはあるか。** 写真・実績・料金・原稿。無いなら3案出しても選べない → 先に揃える
- **既存サイトはあるか。** あれば必ず実ページを WebFetch し、**実際の文言を抜く**
  （提案で使うコピーは、勝手に創作せず既存の言葉を優先する）
- **どちらに軸を振るか。** 構成が争点か、見た目が争点か（後述 Phase 5）

既存サイトがある場合、**最大の資産が埋もれていないか**を探す。
実サイトの中に、本人が価値と気づいていない強い証拠（独自の撮影方法・特殊な体制・
第三者認証）が眠っていることが多い。これが①〜③すべての軸を貫く核になる。

## 2. 案件条件を検索キーへ翻訳

参照台帳がある場合はそれを使う:
`c:\work\ai-ideas\idea-engine\reference\taste\_search-keys.md`（K01〜の翻訳表）

無い／該当しない場合は新規に起こす。翻訳表は最低この4項目:

```
【狙う効果】   信頼 / 課題解決 / 高級感 / 親しみ …
【検索キー】   業種 × 色 × サイト種別 × テイスト
【避けるキー】 この案件で引いてはいけない条件（＋理由）
【判断基準】   候補を見たとき何をもって採否を決めるか
```

**⚠ ギャラリーのタグは「見た目の軸」しかなく、事業目的の軸が無い。**
テイスト名で直接引くと「格好いいが何の会社か分からない」候補が並ぶ。
必ず翻訳表を通してから検索する。

## 3. 複数ページ × 複数軸で検索

**1軸1ページで終わらせない。** 最低でも3方向:

- **業種軸**（例: `美容`）を複数ページめくる
- **色軸**（例: `ベージュ系` `白` `モノトーン`）で**業種を跨いで**引く
- **テイスト軸**（例: `エレガント` `ミニマル・シンプル`）で**業種を跨いで**引く

**業種を跨ぐのが重要。** サロン案件でも、スキンケア/旅館/クリニック/工房が
同じ「暖色ニュートラル × 素材の寄り写真 × 落ち着いた和文」を持っていれば借りられる。

主な狩場:

| ギャラリー | 特徴 |
|---|---|
| MUUUUU.ORG | 約6,000件。業種/色/種別/テイスト/動きの多軸。日本語の縦長LPに強い。最有力 |
| 業種別まとめ記事 | キュレーション。一言評は根拠が薄く**実物確認必須** |

集めたら **実ページを WebFetch で開く**。候補10件前後まで絞り、
色比率・タイポ・写真の扱い・余白・動きを観測して記録する。

## 4. 3軸に振り分ける

集めた候補を**意図的に3つの性格へ**振り分ける。ここが型の中心。

| 軸 | 狙い | 選ぶ基準 | 効く場面 |
|---|---|---|---|
| **① 既存寄り** | 今の延長。抵抗が最小 | 現行の色・構成・トーンに近い | 決裁者が保守的／既存顧客が離れると困る／予算が小さい |
| **② 王道** | その業種で最も「正しい」形 | 同業上位に共通する構造・配色 | 迷ったらこれ。失点最小、ただし差別化はしない |
| **③ 尖り** | 動き・構図・タイポで踏み込む | 動き/レイアウト/写真の扱いが独特 | ブランドを作り直したい／競合と同じに見えるのが最大リスク |

**3案とも同じだけ本気で作る。**

## 5. 構成とデザインを**別軸**で決める（最重要）

| 決めること | 中身 | 決め方 |
|---|---|---|
| **構成（骨格）** | セクション順序・何を最初に出すか・CTAの置き場・情報の粒度 | **事業目的から自前で設計**。ギャラリーから借りない（借りるなら同目的のサイトのみ） |
| **デザイン（見た目）** | 色・余白・写真の扱い・タイポ・動き | **ギャラリーから借りる**。層ごとに1つずつ選ぶ |

**既定**: まず構成を1つ決め、その上にデザイン3案を載せる。
（構成3案 × デザイン3案 = 比較軸が9通りに膨らみ、客が選べない）

**例外**: 構成そのものが争点（情報設計から見直す／何を最初に出すか未定）なら
構成2案 × デザイン各1案。**どちらに軸を振るかを Phase 1 で先に決める。**

### 借りるときの層の分け方

参照を混ぜるときは **層をまたいで1つずつ**選ぶ。同じ層を混ぜると事故る。

| 層 | 例 |
|---|---|
| 骨格 | セクション順序・情報構造 |
| 配色 | 背景/文字/アクセントの比率 |
| タイポ | 見出しと本文の落差・書体の性格 |
| 余白 | 密度 |
| 写真 | クロップ・被写体・色調 |
| 動き | モーションの量と目的 |
| 信頼 | 信頼の作り方（実績数値型／不安先回り型／佇まい型） |

- ✅ 良い例: 「A社の骨格 × B社の余白 × C社のタイポ」← 層が全部違う
- ❌ 悪い例: 「実績数値型 × 課題提示型」← **骨格が2つ**になり主張がぼやける

## 6. 各案にコンセプトと根拠を書く

案ごとに**必ず**この4点。無い案は提出しない。

```
【軸】       既存寄り / 王道 / 尖り
【コンセプト】 一文。何を狙って何を捨てたか
【参照】     実際に開いたサイト名とURL。どの層を借りたか
【捨てたもの】 この案で意図的にやらないこと（＝他案との違いが立つ）
```

さらに **③尖り案には工数差を明記する**。
動き・独自レイアウトは実装/保守が重い。後で揉める原因になる。

## 7. 提示

- 3案を**同じ条件**（同じ実データ・同じ画面幅）で見比べられる形にする
- Artifact で1枚にまとめるのが基本。実装はしない
- 写真が無い場合は**プレースホルダを置き、その旨を明示**する
- 3案の比較表（軸・コンセプト・参照・捨てたもの・工数）を必ず添える

## 8. 在庫へ戻す（省略しない）

選ばれた案・**選ばれなかった案の両方**を参照台帳へ戻す:

- 参照サイトを `tNN-スラッグ.md` で分解保存（`reference/taste/`）
- 使った検索キーを `_search-keys.md` へ追記
- **外れたキーほど再利用価値が高い**（次に同じ空振りをしない）

この工程を省くと、次の案件でまたゼロから探すことになる。
「見つけるのが大変」の再発はここで防ぐ。

# Output

1. **前提の確認結果**（コンテンツの有無・軸の振り方・既存サイトの埋もれた資産）
2. **検索記録**（引いた軸・ページ数・実際に開いたサイトと確認日）
3. **構成案**（骨格。事業目的からの設計として説明する）
4. **デザイン3案**（軸／コンセプト／参照／捨てたもの／工数）
5. **見比べ Artifact**
6. **比較表**
7. **在庫へ戻した記録**

# 完了条件

- [ ] ギャラリーを複数ページ × 複数軸で引いた（1ページで終わっていない）
- [ ] 参照として挙げた全サイトを実ページで開いて確認した
- [ ] 機能条件で候補を絞っていない
- [ ] 3案が軸で選ばれている（当て馬が無い）
- [ ] 各案に軸/コンセプト/参照/捨てたものが揃っている
- [ ] 構成とデザインが分離して提示されている
- [ ] ③尖り案の工数差を明示した
- [ ] 参照サイトと検索キーを在庫へ戻した

# ギャップ（この型が担保しないこと）

1. **ビジネス目的の重み付けは別途。** 3案とも見た目として成立しても、
   売上/問い合わせに効くかは別問題
2. **アクセシビリティ・性能は3案共通の完了条件。**
   尖り案ほどモーション/大画像で LCP・`prefers-reduced-motion` を壊しやすい
3. **3案が多すぎる場合がある。** 小規模改修では2案（既存寄り／王道）で足りる。
   軸の数は案件規模に合わせる
4. **選定後の実装はこのスキルの外。** 選ばれたら
   [[design-variant-preview]] で細部を詰めるか、[[implementation-planner]] へ渡す
