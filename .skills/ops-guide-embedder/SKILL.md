# Purpose

このリポジトリは「サイト量産の原本」であり、各サイトは要件定義書から作られていく。その際に**運営者が「どの画面で何をし、どのコマンド/実行文を Claude Code に貼るか」を画面上で追える操作手順**を、必ずサイトに組み込む。現状の課題は「作ったサイトの操作手順が分かりにくい」こと。これを、画面内の**番号付き実行手順パネル**で解消する。

同時に、この操作手順は**開発・運営のための手順**であり、**製品として第三者に販売・引き渡すときには不要**になる。だから最初から `features/ops-guide/` という1つの隔離ディレクトリに閉じ込め、**フォルダごと削除＋マウント1箇所を消すだけ**で跡形なく消えるように作る。これがこのスキルの2本柱。

参照実装は AI Testmaster の `app/testmaster-client.tsx`（workspace 先頭の番号付き実行手順パネル）と `.howto` 系スタイル。ただし本スキルは **globals.css を触らず、スタイルも隔離ディレクトリ内に閉じる**（削除時に残骸を残さないため。後述）。

# 2本柱（設計思想として必ず守る）

- **手順は画面で完結し、コピーで動く。** 運営者はパネルを上から順に読み、各ステップの Copy ボタンでコマンド/実行文を取って、サイト操作 or Claude Code に貼る。だから各ステップは自己完結（会話文脈なしで意味が通る）で、実行場所が一目で分かるタグを持つ。
- **販売時に一括削除できる隔離。** 操作手順に関わる**全ファイルは `features/ops-guide/` の中だけ**に置く。サイト本体に触るのは**マウント1箇所**（1 import ＋ マーカーで囲んだ1ブロック）のみ。削除は「フォルダを消す」＋「マーカーブロックを消す」の2手で終わる。共有ファイル（globals.css 等）を編集して残骸を残すのは禁止。
- **パスは動的、ハードコードしない。** 選択中プロジェクトの slug から `c:\work\{slug}` を実行時に生成する。別プロジェクトを開けば slug と root が差し替わって同じ手順が出る。ステップ本文に絶対パスを直書きしない（`{slug}` / `{root}` を使う）。
- **改修したら手順も直す。** サイトの操作フロー・コマンド・画面導線を変えたら、`features/ops-guide/steps.ts` の該当ステップも必ず更新する。手順が実態とズレるのが「分かりにくい」の主因。

# When To Use

- 新規サイトを要件定義書から作っていて、運営者向けの操作手順を画面に入れたい
- 既存サイトの操作手順が分かりにくいので、実行手順パネルに置き換えたい
- ディスパッチ方式（[[dispatch-pattern-builder]]）の実行文を、番号付き手順として並べたい
- 将来販売する可能性があり、操作手順を後で一括で剥がせる形にしておきたい

要件自体がまだ曖昧（何を運営するサイトか未確定）なら、先に
[requirements-discovery](../requirements-discovery/SKILL.md) で固める。
本スキルは「操作フローが分かっているサイトに、隔離された実行手順パネルを実装し、維持する」ことに特化する。

# Procedure

### 1. 対象サイトと slug の出所を掴む

推測で埋め込まない。まず次を確認する:

- **フレームワーク**: Next.js App Router + React/TS を既定とする（このリポジトリ原本の標準スタック）。違うなら合わせる。
- **どの画面に出すか**: 運営者が最初に触る画面（例: workspace / ダッシュボード先頭）。testmaster では workspace 先頭。
- **slug の出所**: 「選択中プロジェクトの slug」がどこに持たれているか（選択状態・URL param・props 等）。ここから `root = c:\work\{slug}` を作る。出所が無ければ、パネルに slug を渡す最小の配線を決める。

### 2. 手順ステップを起こす（データとして）

サイトの実際の機能・ルート・存在するディスパッチ受け側スキル（`*-run` 等の実行文）を読んで、運営者が上から順にやる操作を**番号付きで列挙**する。各ステップは構造化データにする（本文直書きではなく `steps.ts` に置く）。スキーマと実行場所タグは
[references/panel-spec.md](references/panel-spec.md) を参照。最低限:

- `no`（順番）
- `place`（`site` / `claude-code` / `other-project` … 実行場所タグ）
- `body`（説明文 or 貼り付けるコマンド・実行文。`{slug}` / `{root}` を含められる）
- `copyable`（コマンド・実行文なら true → Copy ボタンを出す）

testmaster の実例（このパネルが目指す出力）:

| # | 場所 | 内容 / プロンプト |
|---|---|---|
| 1 | サイト | Projects で「{slug}」を選択する |
| 2 | サイト | Context を記入して Save |
| 3 | Claude Code | `{slug} のテスト項目を作って。対象コードは {root}` |
| 4 | Claude Code | `{slug} のAPI項目をテストして記録して` |
| 5 | Claude Code | `{slug} の画面項目をテストして記録して` |

### 3. 隔離ディレクトリを作る

全ファイルを `features/ops-guide/` に閉じる。構成・マウント方法・削除手順は
[references/isolation-and-removal.md](references/isolation-and-removal.md) に従う。要点:

- パネル本体 / ステップデータ / 置換ヘルパ / **スコープドスタイル** / README(削除手順) を全部この中に置く
- **globals.css や共有ファイルは触らない**（削除時に残骸を残さないため。スタイルは CSS Module 等でフォルダ内に閉じる）
- サイト本体に触るのは**マウント1箇所だけ**。マーカーで囲む:

```tsx
{/* ops-guide:start —（販売時は features/ops-guide/ とこのブロックを削除）*/}
<OpsGuidePanel slug={selectedSlug} />
{/* ops-guide:end */}
```

### 4. 動的パスを配線する

`{slug}` → 選択中プロジェクトの slug、`{root}` → `c:\work\{slug}` を**実行時に置換**する。置換は `features/ops-guide/` 内のヘルパに集約する（1箇所で直せるように）。slug 未選択時の空状態も用意する。

### 5. 削除手順を README に固定する

`features/ops-guide/README.md` に、**マウントした正確なファイルパス**と削除2手順を必ず記録する。将来、会話文脈が無い状態でも「これを消せば操作手順が全部消える」と分かるようにする。任意で `uninstall.ps1`（フォルダ削除＋マーカーブロック除去）を同梱してよい。

### 6. 改修時の同期（維持フェーズ）

このスキルを一度使ったサイトでは、**操作フロー・コマンド・画面導線を変えるたびに** `features/ops-guide/steps.ts` を開いて該当ステップを直す。ズレた手順は「分かりにくい」の最大要因。変更が手順に影響するか毎回自問する。

### 7. セルフチェック

- 操作手順の全ファイルが `features/ops-guide/` の中に収まっているか（外に散っていないか）
- サイト本体への変更が**マウント1ブロックだけ**か。globals.css 等の共有ファイルを編集していないか
- マウントが `ops-guide:start` / `ops-guide:end` マーカーで囲まれているか
- ステップ本文に絶対パス直書きが無く、`{slug}` / `{root}` を使っているか
- コマンド・実行文のステップに Copy ボタンが付いているか、貼るだけで動く自己完結文か
- README に「マウントした正確なパス＋削除2手順」が書いてあるか
- 仮に今フォルダとマーカーブロックを消したら、`grep OpsGuide` が 0 件になるか（残骸ゼロ）
- 別プロジェクトを開くと slug / root が差し替わって同じ手順が出るか

# Definition of Done

- [ ] 対象画面の先頭に番号付き実行手順パネルが出る（場所タグ＋Copyボタン付き）
- [ ] slug から `c:\work\{slug}` が動的生成され、別プロジェクトでも差し替わる
- [ ] 操作手順の全ファイルが `features/ops-guide/` に隔離されている
- [ ] サイト本体の変更はマーカーで囲んだマウント1ブロックのみ
- [ ] `features/ops-guide/` を消す＋マーカーブロックを消すだけで操作手順が完全に消える（残骸ゼロ）
- [ ] README に削除2手順とマウントパスが記録されている
