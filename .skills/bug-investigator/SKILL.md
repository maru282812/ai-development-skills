# Purpose

発生している不具合・エラーについて、症状の確定 → レイヤーの切り分け → 原因特定 → 修正方針の提示までを行う。

system-investigator が「正常なシステムの構造を調べる」のに対し、bug-investigator は「壊れている挙動の原因を突き止める」ことに特化する。

対象スタック:
- **Next.js**: ビルドエラー / 実行時エラー / hydration error / Server-Client 境界の問題
- **Supabase**: PostgREST エラー(PGRST系)/ RLS による silent failure / Auth エラー / migration 未適用

# When To Use

- エラーメッセージが出ていて原因を知りたい
- エラーは出ないが期待どおり動かない(白画面、データが出ない、ボタンが効かない)
- build は通るのに本番/開発で動かない
- 「昨日まで動いていたのに動かなくなった」

エラーがなく構造・影響範囲を調べたいだけなら [system-investigator](../system-investigator/SKILL.md)、
データの流れ自体を整理したいなら [data-flow-mapper](../data-flow-mapper/SKILL.md) を使う。

# Procedure

### 1. 症状の確定

曖昧な報告(「動かない」)を観測可能な事実に変換する。不足していればユーザーに確認する:

- **何をしたら**(操作・URL・入力値)
- **何が起きたか**(エラーメッセージ全文 / 画面の状態 / HTTPステータス)
- **いつから**(直前にデプロイ・migration・パッケージ更新があったか)
- **どこで**(ローカル / Vercel等の本番 / 特定ブラウザのみ)

エラーメッセージ・スタックトレースは**全文**を入手する。要約された報告だけで推測しない。

### 2. エラーの一次分類

エラーメッセージから発生レイヤーを分類する。既知パターンは [references/error-patterns.md](references/error-patterns.md) を最初に照合すること(PGRST系・hydration error・白画面はここでほぼ特定できる):

| 分類 | 典型的なシグナル |
|---|---|
| ビルド/型 | `tsc` / `next build` 失敗 |
| Next.js 実行時(Server) | terminal/Vercelログのスタックトレース、500 |
| Next.js 実行時(Client) | ブラウザ console のエラー、白画面、hydration error |
| Supabase API | `PGRST...` コード、`{ error: ... }` レスポンス |
| Supabase Auth | 401、セッション切れ、redirect ループ |
| RLS | **エラーなしで空配列が返る**(最重要パターン) |
| 環境変数 | ローカルでは動くのにデプロイ先で落ちる |

### 3. 再現確認

- ローカルで再現手順を実行し、自分の目で症状を確認する
- 再現しない場合は環境差分(env、migrationの適用状況、データ差分)を疑う

### 4. レイヤーの切り分け

データの流れに沿って「どこまでは正常か」を二分探索する:

1. **DB に正しいデータがあるか**(Supabase Studio / SQL で直接確認)
2. **API/Server Action 単体で正しい値を返すか**(curl / console.log / Route Handler 直叩き)
3. **クライアントに値が届いているか**(Network タブ / レスポンス確認)
4. **UI が値を正しく描画しているか**(props / state の確認)

Supabase クエリは `.select()` の結果だけでなく **`error` オブジェクトを必ず確認**する(握りつぶされていることが多い)。

### 5. 原因の特定と検証

- 仮説を1つ立て、それを裏付ける/否定する**最小の確認**を行う(コードを直す前に検証する)
- 「直したら動いた」ではなく「この行のこれが原因で、この理屈で壊れていた」と説明できる状態にする
- 複数の問題が重なっている可能性に注意(1つ直して再テスト)

### 6. 修正方針の提示

- 根本原因に対する修正と、応急処置(あれば)を分けて提示する
- 同種のバグが他の箇所にもないか横展開検索する
- 再発防止(バリデーション追加、エラーハンドリング、テスト)を提案する
