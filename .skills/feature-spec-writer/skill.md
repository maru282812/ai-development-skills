# Purpose

機能要望を、AI エージェントに 1 回で渡せる完結した実装仕様書に変換する。

各設計スキル(db-designer / api-designer 等)が個別領域を深掘りするのに対し、feature-spec-writer は**1機能を端から端まで1ドキュメント**にまとめることに特化する。出力はそのまま Codex / Claude Code に貼って実装を開始できる粒度にする。

# When To Use

- 機能要望が固まっていて、AI エージェントに渡す指示文が欲しい
- 口頭・チャットで散らばった仕様を1つの仕様書に統合したい
- 外部の開発者・AIに渡す引き継ぎドキュメントが欲しい

要件がまだ曖昧(MVP範囲・ユーザー種別が未定)なら先に [saas-product-manager](../saas-product-manager/skill.md)、
大規模で実装順序の計画が必要なら [implementation-planner](../implementation-planner/skill.md)、
DB・API設計だけ深掘りしたいなら [db-designer](../db-designer/skill.md) / [api-designer](../api-designer/skill.md) を使う。

# Procedure

### 1. 要件の確定

- 機能の目的・対象ユーザー・ユースケースを確認する
- 未確定事項があれば**仕様書を書く前に**ユーザーに確認する(推測で書かない)
- スコープ外(今回やらないこと)を明文化する

### 2. 既存コードの前提確認

仕様書は既存コードベースと整合していなければ実装に使えない。最低限以下を確認する:

- 関連する既存テーブル・既存画面・既存API(必要なら [system-investigator](../system-investigator/skill.md) の手順で調査)
- プロジェクトの規約: App Router / Pages Router、Server Action か Route Handler か、UIライブラリ、バリデーション方式
- 認証方式と既存の権限モデル

### 3. 仕様の各セクション作成

以下の順で埋める。**後のセクションは前のセクションと矛盾しないこと**(画面にある項目はDBに対応カラムがある、APIは画面の操作と1対1で対応する等):

1. **目的**: 1〜3文。なぜ作るか
2. **画面**: 画面ごとに URL・表示項目・操作・状態(空/ローディング/エラー)
3. **API / Server Actions**: エンドポイントまたは関数ごとに入出力・バリデーション・エラーレスポンス
4. **DB**: 新規/変更テーブルの DDL(migration SQL)、インデックス
5. **権限**: 操作×ロールのマトリクスと、RLS ポリシーの方針
6. **受け入れ条件**: 「〜できる」「〜の場合は〜になる」形式で検証可能に書く(正常系+主要な異常系)

### 4. 実装指示文の作成

仕様書の末尾に、AI エージェント向けの指示文を付ける:

- 実装順序(migration → API → 画面 の順を明示)
- 守るべきプロジェクト規約(ディレクトリ、命名、使用ライブラリ)
- 触ってはいけない箇所(既存機能への影響禁止事項)
- 完了確認方法(`tsc` / `lint` / `build` と受け入れ条件の照合)

### 5. セルフチェック

- 画面の全項目に DB カラムの対応があるか
- 全操作に権限の定義があるか
- 受け入れ条件だけ読んで完成判定ができるか
- この仕様書**単体**で(会話の文脈なしで)実装に着手できるか

# Output Template

```md
# 実装仕様書: <機能名>

## 目的

## スコープ外
- (今回やらないこと)

## 画面
### <画面名>(URL: /path)
- 表示項目:
- 操作:
- 状態: (空 / ローディング / エラー時の表示)

## API / Server Actions
### <名前>
- 種別: Route Handler / Server Action
- 入力: (型・バリデーション)
- 出力: (成功時 / エラー時)
- 認可: (誰が呼べるか)

## DB
\```sql
-- migration SQL
\```
| テーブル | カラム | 型 | 制約 | 用途 |
|---|---|---|---|---|

## 権限
| 操作 | ロールA | ロールB |
|---|---|---|
- RLS方針:

## 受け入れ条件
- [ ] (正常系)
- [ ] (異常系)

## 実装指示
(AIエージェントにそのまま渡す部分)
1. 実装順序:

3. 禁止事項:

```
