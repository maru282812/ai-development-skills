# プロジェクト作成（アイデア → 実装プロジェクトの立ち上げ）

アイデア相談の場（主に ai-ideas）で固まった内容を、実装用プロジェクトとして立ち上げる。
フォルダ作成 → 引継ぎ書配置 → git/GitHub 初期化までを一気通貫で行う。
ゴールは「引き継ぎ先で新しいセッションを開いたとき、引継ぎ書1枚を
読むだけでこの会話の文脈が完全に復元できる」状態。ここで手を抜くと、引き継ぎ先の
セッションが同じ質問をユーザーに繰り返すことになる（それを防ぐのが本スキルの存在理由）。

## 手順

### 1. 引き継ぎ先フォルダを特定・作成する

- ユーザーの発話からプロジェクト名を取る（例: 「survey-tabulation プロジェクト作成」）。
- `c:\work\<name>` を既定とする（ユーザーが別パスを言えばそちら）。
  **必ず先に `c:\work` 直下を Glob して近い名前の既存フォルダが無いか照合する**
  （似た名前の既存フォルダを見落として重複プロジェクトを作らない）。
- 既存フォルダがあればそれを使う。無ければ `c:\work\<name>` を**作成する**（確認不要。
  既定パス以外へ作る場合だけユーザーに確認する）。
- 引き継ぎ先に既存ファイル（雛形コード・README 等）があっても**一切上書きしない**。
  本スキルが触ってよいのは `docs\handoff.md`・`docs\reference\`・CLAUDE.md への追記、
  および §5 の git 初期化だけ。

### 2. 引継ぎ書を確保する

引継ぎ書が本スキルの中核。優先順位:

1. **既存の引継ぎ書があるならそれを使う** — 相談元プロジェクトの `docs/*handoff*.md` を Glob で探し、
   会話の話題と一致するものがあればそれが原本。会話でその後に確定した事項があれば原本を更新してから渡す。
2. **無ければ会話から生成する** — 相談元の `docs/<name>-handoff.md` として保存する（原本は相談元に残す）。

生成時の構成（実績のある型。`c:\work\ai-ideas\docs\survey-aggregation-app-handoff.md` が見本）:

```
# 引継ぎ書: <プロジェクト名>
作成日 / 作成元 / 位置づけ（新プロジェクト立ち上げ時に文脈を復元するための1枚）
1. 何を作るか（1段落で）
2. 確定済みの前提（覆さないこと）— 会話でユーザーが確定した決定事項
3. 技術方針 — 選定と理由の表
4. アーキテクチャ / 全体フロー
5. Phase計画
6. 参照資料の場所 — 資料 / 場所 / 用途 の表
7. 新プロジェクト立ち上げ手順（そのまま実行できる形）
8. 未解決・次に確認すること — チェックボックス形式
```

**書いてよいのは会話で実際に決まったことだけ。** 決まっていない点をもっともらしく埋めない —
それは §8「未解決」へ落とす。引継ぎ書の読み手は文脈ゼロの新セッションなので、
「例の件」「さっきの方針」のような会話内参照を残さず、すべてその場で言い切る。

### 3. 参照資料を引き継ぎ先へ同梱する

引継ぎ書が参照しているローカルファイルを `<target>\docs\reference\` へコピーする。

- 対象: 相談元プロジェクト内の資料（壁打ちログ、設計テキスト等）、`Downloads` などの
  **消えやすい場所にある資料は特に必ず**コピーする（PDF マニュアル等）。
- 他のアクティブなリポジトリ内のソースコード（例: 別アプリの実装ファイル）はコピーしない —
  更新され続けるものはパス参照のままが正しい。
- 参照先が見つからないファイルはコピーを諦めて、引継ぎ書の該当行に「⚠ 元ファイル所在不明・入手先: …」と残す。
- コピー後、引継ぎ書内のパスを引き継ぎ先から見えるパスに書き換えた**コピー版**を
  `<target>\docs\handoff.md` として置く（相談元の原本はそのまま）。

### 4. 引き継ぎ先にファイルを置く

```
<target>\
├── docs\
│   ├── handoff.md          ← 引継ぎ書（パス書き換え済みコピー）
│   └── reference\          ← 同梱資料
└── CLAUDE.md               ← 道しるべ（無ければ新規、あれば追記）
```

- `docs\` が既にあればその中に置く（既存ファイルと名前が衝突したら `handoff-<name>.md` に避ける）。
- CLAUDE.md が**無い**場合は最小のものを新規作成する（詳細は handoff.md に集約されているため）:

```markdown
# <プロジェクト名>

<何を作るか 1行>

## 最初に読むもの
- docs/handoff.md — 構想時の全文脈（確定事項・技術方針・Phase計画・未解決事項）。作業開始前に必ず読む。

出典: <相談元プロジェクト> での構想相談（<日付>）
```

- CLAUDE.md が**既にある**場合は上書きせず、「## 最初に読むもの」の節だけを末尾に追記する。

### 5. git/GitHub を初期化する

docs 配置が終わったら、[[git-init-setup]] のスクリプトを引き継ぎ先に対して**実行する**
（案内で止めない。§4 の後に実行するのは、初回コミットに handoff.md / reference / CLAUDE.md を
含めるため）:

```powershell
powershell -ExecutionPolicy Bypass -File C:\work\ai-development-skills\.skills\git-init-setup\scripts\setup-git.ps1 -Path <target>
```

- git-init-setup の安全ガードはそのまま効かせる: 引き継ぎ先が「コミット履歴＋remote あり」の
  既存リポジトリならスクリプトが自動中断して保護する（**勝手に -Force を付けない**。
  その場合 git は既に整っているので、そのまま §6 へ進んでよい）。
- `gh` 未認証で中断したら、docs 配置までは完了している旨と `gh auth login` 後に
  「git作成」で再開できる旨を伝える（docs 配置をやり直す必要はない）。
- リポジトリは **private** が既定。

### 5.5 製造ループ基盤を設置する（factory-bootstrap）

git 初期化が終わったら、[[factory-bootstrap]]（`C:\work\ai-development-skills\.skills\factory-bootstrap\SKILL.md` を
Read して従う）で引き継ぎ先に製造ループ基盤を設置する:

- `docs\VERIFY.md`（検証レシピ）・`.claude\loop.md`（保守ループ既定）・CLAUDE.md への「製造ループ」節追記。
- 立ち上げ直後でコードが無い場合、VERIFY.md の Gates / Runtime Verify は `<TODO>` のまま置いてよい
  （雛形コード生成後の最初のセッションが具体化する。その旨を引継ぎ書 §8「未解決」に1行足す）。
- 設置分は追加コミットする（メッセージ例: `chore: 製造ループ基盤を設置 (factory-bootstrap)`）。

### 6. 完了報告と次の一手

置いたファイル一覧と GitHub リポジトリ URL を示し、次の手順を案内する（実行はしない）:

1. 引き継ぎ先で Claude Code を開く（`cd <target>`）
2. 引継ぎ書 §7 の立ち上げ手順に従って実装開始（雛形コード生成は引き継ぎ先の最初のセッションの仕事）

### 7. 相談元の記録を更新する

- 相談元プロジェクトの memory に「<アイデア名> は <target> へ引き継ぎ済み（<日付>）。
  引継ぎ書 = docs/<name>-handoff.md」を記録する（既存の該当 memory があればそれを更新）。
- これで次回 ai-ideas 側の会話が「そのアイデアはもう実装フェーズ」であることを思い出せる。
- **管制塔索引を更新する** — `c:\work\ai-ideas\docs\projects-index.md` の台帳に
  今回のプロジェクトの行を追加する（既に行があれば状態・引継ぎ書リンクを更新）。
  列: プロジェクト / 場所 / 状態 / 目的（1行） / 引継ぎ書・主要文書 / 依存・連携 / 最終確認。
  状態は `構想` / `active` / `休止` / `完了` / `要確認` の5種から選ぶ。
  相談元が ai-ideas 以外でも、索引の場所はこの絶対パスで固定。

## やらないこと

- **git の運用設定（CI/CD・ブランチ保護・Issue テンプレ等）** — 初期化（init〜GitHub private〜push）
  までは §5 で行うが、その先は対象外。
- **既存リポジトリの作り直し（-Force 実行）** — git-init-setup のガードで中断したら保護を優先。
- **雛形コード生成（Next.js 等のスキャフォールド）** — 引き継ぎ先の最初のセッションの仕事。
- **要件の追加発明** — 会話で決まっていないことを引継ぎ書に書かない。
- **引き継ぎ先の既存ファイルの上書き・削除** — 触るのは docs\handoff.md / docs\reference\ / CLAUDE.md への追記、および git 初期化のみ。
