# Purpose

Next.js で作られた画面(管理画面・LIFF・スマホ向け画面)を対象に、
ユーザーが迷わず目的を達成できるかを確認し、具体的な改善案と実装指示を出す。

必ず扱う観点:

- 画面目的(この画面でユーザーが達成したいことは何か)
- ユーザー導線(エントリ→完了までの流れ、迷い・行き止まり)
- 入力フォーム(項目数、順序、入力支援、バリデーションのタイミング)
- エラー表示(気付けるか、次の行動がわかるか)
- 空状態(データ0件時に何をすべきかわかるか)
- ローディング(待ち状態の表示、レイアウトシフト)
- スマホ表示(タップ領域、横スクロール、キーボード)
- 管理画面の一覧 / 詳細 / 編集パターン
- CTA(主要アクションが目立つか、1画面1主ボタン)
- 文言(ユーザーの言葉か、エラーが次の行動を示すか)

# When To Use

- 実装した画面の使いやすさを確認・改善したい
- 管理画面の一覧・詳細・編集の構成を良くしたい
- フォームの離脱・入力ミスを減らしたい
- スマホ(LIFF含む)での使い勝手を確認したい
- ボタン配置・文言に迷っている

機能仕様そのものの整理は [saas-product-manager](../saas-product-manager/skill.md)、
コードの品質確認は [code-review](../code-review/skill.md) を使う。

# Procedure

### 1. 画面目的とユーザーの確認

- 対象画面と、その画面の利用者(管理者 / エンドユーザー / スマホ前提か)を確認する
- 「この画面でユーザーが達成したいこと」を1文で定義する。複数ある場合は主目的を決める

### 2. 実装の確認

- 対象画面のコンポーネント・ページを読み、現状のUIを把握する
  (画面の特定は [system-investigator の nextjs.md](../system-investigator/references/nextjs.md) セクション1)
- スクリーンショットや実際の動作確認が可能なら実施する

### 3. 導線の確認

- エントリポイント(どこからこの画面に来るか)→ 完了 → 完了後の遷移先、を追う
- 迷うポイント(次に何をするかわからない)、行き止まり(戻れない・完了がわからない)を探す

### 4. 状態別の確認

- 空状態 / ローディング / エラー / 正常(少量・大量データ)の4状態すべてに表示があるか確認する
- チェック項目は [references/ui-ux.md](references/ui-ux.md) セクション1を使用する

### 5. フォーム・CTA・文言の確認

- フォーム: [references/ui-ux.md](references/ui-ux.md) セクション2のチェックリストを通す
- CTA: 主要アクションが視覚的に1つ際立っているか、破壊的操作に確認があるか
- 文言: システム都合の言葉(「不正な値です」等)をユーザーの言葉に置き換える

### 6. スマホ・レスポンシブの確認

- スマホ幅(375px目安)での表示、タップ領域(44px目安)、テーブルの横スクロール対策を確認する
- LIFF の場合は [references/ui-ux.md](references/ui-ux.md) セクション3の固有観点も確認する

### 7. 改善案の優先度付けと実装指示

- 指摘を「導線の問題(目的達成を阻む)/ 改善案 / 文言修正」に分類し、優先度を付ける
- 上位の改善はそのままAIエージェントに渡せる実装指示にする

# Output Template

```md
# UI/UXレビュー: <画面名>

## UI/UX総評
(目的を達成できる画面になっているかの総合判断。2〜3文)

## 画面目的
(この画面でユーザーが達成すること)

## 導線の問題
| # | 箇所 | 問題 | 影響 |
|---|---|---|---|

## 改善案
| 優先度 | 箇所 | 現状 | 改善案 |
|---|---|---|---|

## 文言修正
| 箇所 | 現状 | 修正案 |
|---|---|---|

## スマホ対応
- (スマホ幅・タップ領域・キーボードの問題と対応)

## 実装指示
(優先度高の改善をまとめて、そのままAIエージェントに貼れる形で)
```

実例は [examples/](examples/README.md) を参照。
