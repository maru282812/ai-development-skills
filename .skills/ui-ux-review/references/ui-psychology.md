# UI心理学・行動経済学 原則集（UI設計の必須参照）

画面のUIを考えるとき（新規設計・リデザイン・レビューのすべて）は、**必ずこのファイルの原則に照らして判断する**。
「なんとなく良さそう」ではなく「どの原則に基づくか」を根拠として明示すること。

利用スキル: hallmark（見た目）/ screen-design-architect（画面設計）/ ui-ux-review（レビュー）。
**このファイルが正本**（2026-11-02 一本化）。hallmark の `references/psychology.md` は工程への差し込み方だけを持ち、原則の中身はここを読む。原則を足す・直すときはここだけを直す。

---

## 使い方（3ステップ）

1. **設計前**: 対象画面のタイプを特定し、§4 の画面タイプ別マッピングから適用原則を選ぶ（3〜7個。全部盛りにしない）
2. **設計中**: 各UI判断（配置・数・順序・文言・デフォルト値）に、選んだ原則を根拠として紐付ける
3. **設計後**: §6 のチェックリストを通し、§5 の倫理ガード（ダークパターン禁止）を確認する

出力には必ず「**適用原則**」の欄を設け、`原則名 → 具体的な適用箇所` の形で記録する。

## §1. 認知心理学の法則（迷わせない・疲れさせない）

| 原則 | 内容 | UIへの適用 |
|---|---|---|
| ヒックの法則 | 選択肢が増えるほど決定時間が伸びる | メニュー・CTA・フォーム選択肢は絞る。1画面1主目的。段階的開示（progressive disclosure） |
| フィッツの法則 | 大きく近いターゲットほど速く押せる | 主CTAは大きく・親指/カーソルの動線上に。スマホは画面下部、タップ領域44px以上 |
| ミラーの法則 | 短期記憶は7±2（実務は4±1）チャンク | 情報は3〜5個のグループに分割。電話番号・コードは区切って表示 |
| ヤコブの法則 | ユーザーは他サイトの経験でUIを予測する | 慣習に従う（ロゴ左上=ホーム、カート右上、検索は虫眼鏡）。独自性は慣習を壊さない範囲で |
| ゲシュタルト（近接・類同・連続） | 近い/似ているものは同じグループと認知される | 関連要素は近く、無関係は余白で離す。同機能は同じ見た目に統一 |
| 認知負荷理論 | ワーキングメモリは有限。無関係な負荷は理解を妨げる | 装飾的ノイズを削る。1画面で覚えさせない（入力済み情報を再表示する） |
| テスラーの法則 | 複雑性は消せない。誰が負担するかだけ選べる | ユーザーに押し付けず、システム側が負担（自動補完・住所自動入力・賢いデフォルト） |
| ドハティの閾値 | 応答400ms以内で没入が保たれる | 即時フィードバック必須。待ちはスケルトン/進捗表示、楽観的更新（optimistic update） |
| フォン・レストルフ効果 | 異質なものだけが記憶に残る | 目立たせるのは1画面1要素だけ。全部目立たせる=何も目立たない |
| 美的ユーザビリティ効果 | 美しいUIは「使いやすい」と知覚され、小さな不満が許容される | 見た目の質は機能の一部。ただし美しさで導線の欠陥は隠れない（レビューでは分離して評価） |
| 系列位置効果 | 先頭と末尾が記憶に残る | ナビ・リストの先頭と末尾に重要項目。中間に埋めない |
| ザイガルニク効果 | 未完了のタスクは記憶に残り続ける | プログレスバー・「あと1ステップ」表示で完了へ牽引。中断復帰を設計する |
| 目標勾配効果 | ゴールに近づくほど行動が加速する | 進捗は0%から始めない（例: 登録済み分を進捗に含め20%開始）。残ステップを可視化 |
| ピークエンドの法則 | 体験の評価はピークと終わりで決まる | 完了画面・成功時を丁寧に作る。エラー(谷)の直後にリカバリー導線を置く |

## §2. 行動経済学の原則（行動を後押しする）

| 原則 | 内容 | UIへの適用 |
|---|---|---|
| デフォルト効果 | 人は初期設定のまま使う | 最善のデフォルト値を選んで設定する。推奨プラン・推奨設定を事前選択（ただし §5 の同意事項は除く） |
| 損失回避 | 損の痛みは得の喜びの約2倍 | 「得られるもの」より「失うもの/逃すもの」の文言が効く場面がある（例:「保存されていない変更があります」）。乱用しない |
| アンカリング | 最初に見た数字が基準になる | 価格表は上位プランや通常価格を先に提示。割引は元値を併記 |
| フレーミング効果 | 同じ事実でも表現で選択が変わる | 「成功率95%」vs「失敗率5%」。ポジティブフレーム基本、注意喚起のみ損失フレーム |
| 社会的証明 | 他者の行動が判断材料になる | 利用者数・レビュー・「人気」バッジ。**実データのみ。捏造は禁止**（hallmark の honest copy 原則と同一） |
| 希少性・緊急性 | 手に入りにくいものは価値が高く見える | 在庫残・期限表示は**事実である場合のみ**。偽カウントダウンはダークパターン（§5） |
| おとり効果（非対称優位） | 明らかに劣る第3の選択肢が比較を単純化する | 3プラン構成で中位/上位を選びやすくする。ただし選択肢自体は正直に設計。**大規模追試で再現しにくく、効果を前提にしない**（§2-1） |
| 選択過剰（決定麻痺） | 選択肢過多は選択回避を生む | プランは3〜4個まで。フィルタで絞り込ませる。推奨を1つ明示。効果は条件付き（§2-1） |
| 現在バイアス | 今の小さな報酬 > 将来の大きな報酬 | 価値を先に体験させる（登録前に試させる）。オンボーディングは即座に最初の成功体験へ |
| 授かり効果 | 所有した(と感じた)ものは手放しにくい | 試用中に「自分のデータ・自分の設定」を作らせる。パーソナライズは早期に |
| コミットメントと一貫性 | 小さなYESが次のYESを生む | 大きなフォームは小さなステップに分割し、簡単な質問から始める（foot-in-the-door） |
| サンクコスト | 投じたコストが撤退を妨げる | 入力済み内容は絶対に消さない（自動保存・下書き）。離脱時は進捗保持を伝える |

### §2-1. 効き目の強さ（優先順位はこれで決める）

原則は同じ重さではない。実験データの要約（詳細と出典は hallmark `references/research.md` §2-1。直すときは両方そろえる）:

| 強さ | 原則 | 根拠 |
|---|---|---|
| 強 | 希少性・社会的証明・デフォルト効果 | 6,700 実験のメタ分析で +2.9% / +2.3%、デフォルトは 58 研究で d=0.68。**実データ連動のみ** |
| 中 | 緊急性・選択肢を減らす・損失回避・ピークエンド | 緊急性 +1.5%。選択過剰は研究により有意〜ほぼ 0。損失回避・ピークエンドは Web での定量根拠が薄い |
| 弱 | おとり効果（松竹梅） | 大規模追試で 91 試行中 約 11 しか再現せず |
| ほぼゼロ | 色・ボタンの見た目・CTA 文言の変更 | 同メタ分析で 0.0% / −0.2% / −0.3%。見た目は信頼の下限を守るもので、成果を約束する手段にしない |

## §3. 記憶より認知（Recognition over Recall）

- 思い出させるな、見せて選ばせろ: 履歴・候補・最近使った項目を提示する
- コマンドより選択肢、空欄より例（プレースホルダは例示、ラベルの代替にしない）
- エラーメッセージは「何が起きたか＋次に何をすべきか」をその場に表示（コードだけ出さない）

## §4. 画面タイプ別 適用マッピング

設計対象の画面タイプに応じて、優先的に適用する原則を選ぶ。

| 画面タイプ | 優先適用原則 |
|---|---|
| フォーム / 登録 | テスラー（自動補完）・コミットメント（分割）・サンクコスト（自動保存）・認知負荷・ミラー（グループ化）・ザイガルニク（進捗） |
| 一覧 / ダッシュボード | ヒック（絞る）・ゲシュタルト（グループ）・系列位置・フォン・レストルフ（強調1つ）・Recognition（フィルタ/検索） |
| LP / マーケティング | 社会的証明・アンカリング・フォン・レストルフ（CTA）・美的ユーザビリティ・フレーミング・ピークエンド |
| 価格 / プラン選択 | アンカリング・おとり効果・選択過剰（3〜4案+推奨）・デフォルト効果・損失回避（年払い訴求等） |
| オンボーディング | 現在バイアス（即成功体験）・目標勾配（進捗20%開始）・授かり効果（早期パーソナライズ）・ザイガルニク |
| 設定 / 管理画面 | ヤコブ（慣習）・デフォルト効果（最善初期値）・ヒック（段階的開示）・Recognition・ドハティ（即時反映） |
| エラー / 空状態 | ピークエンド（リカバリー導線）・Recognition（次の行動提示）・テスラー（システムが解決策を提示） |
| 完了 / 成功画面 | ピークエンド（丁寧に作る）・ザイガルニク（次のタスク提示）・社会的証明（共有導線） |
| 削除 / 破壊的操作 | 損失回避（失うものを明示）・デフォルト効果（安全側をデフォルト）・フィッツ（危険ボタンは離す・小さく） |

## §5. 倫理ガード — ダークパターン禁止（必須）

行動経済学の原則は**ユーザーの利益と事業の利益が一致する方向にのみ**使う。以下は原則の悪用であり、検出したら設計を差し戻す。

- **偽の希少性・緊急性**: 事実でないカウントダウン・偽の在庫残・偽の「他のn人が閲覧中」
- **捏造された社会的証明**: 偽レビュー・invented metrics（「50,000+ teams」等の創作数字）
- **コンファームシェイミング**: 拒否ボタンを侮辱的文言にする（「いいえ、損したいです」）
- **ローチモーテル**: 登録は1クリック、解約は迷路
- **こっそりカゴ入れ・事前選択の悪用**: 同意・課金・メール購読のデフォルトON
- **視覚的干渉**: 拒否側を見えにくくする、広告をコンテンツに偽装する
- **強制連続性**: 無料期間終了の無通知課金

判定基準: 「その仕掛けをユーザーに説明したとき、ユーザーが納得するか」。説明できない仕掛けはダークパターン。

## §6. 設計後チェックリスト

出力前に全項目を通す。NG があれば修正してから出す。

- [ ] 1画面の主目的は1つで、主CTAは視覚的に1つ際立っているか（フォン・レストルフ / ヒック）
- [ ] 選択肢・メニュー・フォーム項目は必要最小限か。段階的開示で減らせないか（ヒック / 選択過剰）
- [ ] 主要操作のターゲットは十分大きく、届く位置にあるか。スマホでタップ領域44px以上か（フィッツ）
- [ ] 情報は3〜5個のチャンクにグループ化され、余白でグループが分かるか（ミラー / ゲシュタルト）
- [ ] 一般的なUI慣習から逸脱していないか。逸脱には根拠があるか（ヤコブ）
- [ ] ユーザーの負担をシステム側が肩代わりしているか（自動補完・賢いデフォルト・自動保存）（テスラー / サンクコスト）
- [ ] すべての操作に400ms以内のフィードバックがあるか。待ちは進捗表示があるか（ドハティ）
- [ ] 複数ステップの処理に進捗表示があり、中断復帰できるか（ザイガルニク / 目標勾配）
- [ ] 完了画面・成功時は丁寧に作られ、エラー時はリカバリー導線があるか（ピークエンド）
- [ ] 思い出させる設計になっていないか。候補・履歴・例を見せているか（Recognition over Recall）
- [ ] デフォルト値は「ユーザーにとって」最善か（デフォルト効果 + §5）
- [ ] 数字・実績・希少性表示はすべて事実か（§5 ダークパターン禁止）
- [ ] 出力に「適用原則」欄があり、原則→適用箇所の対応が明記されているか
