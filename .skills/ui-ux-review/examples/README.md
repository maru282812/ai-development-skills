# examples

ui-ux-review の使用例。実際のレビュー結果は `<画面名>.md` でこのディレクトリに追加する。

## 例1: 管理画面のユーザー一覧の改善

### 入力例

> 管理画面のユーザー一覧(/admin/users)が使いにくいと言われた。UI見て、使いやすくして。スマホでも使いたいらしい。

### Skill が見る観点

- 画面目的: 「特定のユーザーを探して詳細・対応に進む」が主目的と定義
- 導線: 検索がない/フィルタがないと件数増加で破綻する。行クリックで詳細に行けるか
- 状態: 0件時・検索0件時の表示、ローディング(スケルトン)、エラー時の表示
- 一覧の情報設計: ステータスがテキストでバッジ化されていない、登録日のフォーマット
- スマホ: 8列テーブルが横スクロール → 重要4項目のカード表示へ切り替え
- 破壊的操作: 行内に「削除」ボタンが露出 + 確認なし → メニューに収納 + 確認ダイアログ

### 出力例(短縮版)

```md
# UI/UXレビュー: 管理画面ユーザー一覧

## UI/UX総評
一覧表示はできているが「探す」手段がなく、件数が増えると目的を達成できない。
削除ボタンの露出は誤操作リスクが高く優先対応を推奨。

## 導線の問題
| # | 箇所 | 問題 | 影響 |
|---|---|---|---|
| 1 | 一覧上部 | 検索・フィルタなし | 100件超でユーザーを探せない |
| 2 | 行内削除ボタン | 確認なしで即削除 | 誤操作で取り返しがつかない |

## 改善案
| 優先度 | 箇所 | 現状 | 改善案 |
|---|---|---|---|
| 高 | 上部 | なし | 名前/メールの検索ボックス + ステータスフィルタ |
| 高 | 行内操作 | 削除が露出 | ⋯メニューに収納し、確認ダイアログ(対象名表示)を追加 |
| 中 | ステータス列 | テキスト | バッジ化(有効=緑/無効=グレー) |
| 中 | スマホ | 横スクロール | md未満は名前・メール・ステータス・登録日のカード表示 |

## 文言修正
| 箇所 | 現状 | 修正案 |
|---|---|---|
| 削除確認 | 本当によろしいですか? | 「山田太郎さんを削除しますか?この操作は取り消せません」 |

## 実装指示
app/admin/users/page.tsx と関連コンポーネントを修正:
1. 検索ボックス(名前・メール部分一致)を追加。searchParams で状態管理 ...
```
