# 実装前ブリーフ（次工程引き渡し用）

更新日: 2026-06-21

## 結論

MVPの推奨構成は、Expo + React Native + TypeScript + Supabase + Google Maps Platform。プロダクト体験は「トイレ検索」ではなく、`今すぐトイレ` と駅/施設の安心トイレ攻略に寄せる。

初期価値は、現在地周辺検索、駅攻略、写真ステップ式ルート投稿、トイレ詳細の階層情報、最短候補・安心候補・代替候補の提示。商業施設攻略はPhase1ではフル機能にせず、現在地/駅周辺の代替候補として基本表示に留める。収益仮説は、導線の目印広告、スポンサーコード、公式情報掲載、エリア協賛、公式ルートカード。

初期リリース対象国は日本国内のみ。海外対応は将来候補として、国、地域、言語、通貨、タイムゾーン、データ信頼度、公式ソース種別を扱える余地だけ残す。
初期対象エリアは関東を主対象にし、大阪・福岡は空港/主要駅ハブに絞って初期拡張対象にする。関東では羽田空港、成田空港、東京、新宿、渋谷、池袋、品川、上野、横浜、大宮、千葉を優先候補にし、大阪/福岡では大阪/梅田、新大阪、なんば、関西国際空港、伊丹空港、博多、天神、福岡空港を優先候補にする。

## 技術選定案

| 候補 | 評価 | 向いているケース | CLEAN TOILETでの判断 |
|---|---|---|---|
| Swift / SwiftUI | iOSで高速・安全。Apple体験に最適化しやすい | iPhone専用で始める、iOS体験を極限まで磨く | Androidも必要なのでMVP第一候補にはしない |
| React Native + Expo | iOS/Android/WebをTypeScriptで共通化しやすい。Expoが開発・配布・更新を支援 | 少人数で両OS対応、地図・カメラ・位置情報を早く作る | 第一候補 |
| Flutter | 単一コードベースでiOS/Android/Web/Desktopに展開でき、UI一貫性が高い | Dart採用に抵抗がなく、独自UIを強く作りたい | 第二候補 |
| ネイティブ iOS + Android | 最高のOS最適化が可能 | 開発者が十分にいて長期保守できる | 初期は開発コストが重い |
| Web/PWA先行 | 最速で検証しやすい。アプリストア審査がない | LP・管理画面・スポンサー申込・簡易デモ | 本体の初期公開形態にはしない |

## 推奨アーキテクチャ（MVP）

| 領域 | 推奨 | 理由 |
|---|---|---|
| モバイルアプリ | Expo + React Native + TypeScript | iOS/Androidを共通化し、Expoの開発・配布導線を使える |
| 管理画面 | Next.js または Expo Web/React Web | 投稿管理・通報対応・スポンサー簡易管理はPCのWeb管理が現実的 |
| DB | Supabase Postgres | 駅/施設/フロア/トイレグループ/投稿/広告を関係DBで扱いやすい |
| 位置検索 | Supabase PostGIS | 近い順検索・表示範囲検索に向く |
| 認証 | Supabase Auth | 投稿者管理、称号、管理者ログインに必要 |
| 画像保存 | Supabase Storage | 写真ステップ投稿に必要 |
| サーバー処理 | Supabase Edge Functions | 通報通知、画像処理、外部API保護に使える |
| 地図 | Google Maps Platform | Maps SDK / Places / Geocoding が候補。費用は要確認 |
| 外部サービス費用管理 | 管理画面の台帳 + 手入力/CSV出力 | 料金・無料枠・API制限は変わるため、公式URLと確認日つきで運用管理する |
| Git | GitHub | issue/PR/tag/releaseで段階管理しやすい |

## データ構造の前提（概念）

実装設計ではないが、要件上は以下の階層を前提にする。

```text
施設/駅
  └ フロア/改札/エリア
      └ トイレグループ
          ├ 男性
          ├ 女性
          ├ 共用
          ├ 多目的
          └ ベビー/オストメイト等
```

写真ステップ投稿は、トイレグループまたは特定種別に紐づく。スポンサー目印はルートカードまたは駅/施設攻略ページに紐づく。

地点提案はログイン済みユーザーに紐づける。ゲストは新規地点提案をできない。提案ステータスは少なくとも、提案中、確認待ち、公開、却下、統合、非公開を扱う。短時間大量登録は投稿者・時間・距離・建物ID・階数・種別で判定し、同一建物内の正当な複数登録は建物単位の登録セッションとして扱う。

写真投稿はログイン済みユーザーに紐づける。画像ステータスは少なくとも、アップロード中、スキャン中、自動ぼかし済み、確認待ち、公開、非公開、通報中を扱う。トイレ内写真フラグ、投稿前確認の同意履歴、注意通知履歴、投稿制限状態を扱えるようにする。

安心度は単純平均ではなく重み付けスコアにする。清潔度は強めに反映しつつ独立表示する。入れなかった、入ったが使えなかった、満室だった、怖い/不安だった、汚すぎた、故障/閉鎖、利用制限あり等は、平均値に混ぜず、注意フラグと強い減点として扱う。

外部サービス費用管理では、サービス名、用途、契約者、請求先、契約プラン、公式料金URL、商用利用条件URL、無料枠、API制限、確認日、月額見込み、実請求額、アラート閾値を扱う。初期はAPI自動連携せず、管理者の手入力とCSV出力でよい。

アップロード先管理では、写真ステップ、トイレ内写真、自動ぼかし後画像、原本保管、通報証跡、レポート、ログをデータ種別ごとに分け、保存先、バケット/コンテナ、リージョン、公開/非公開、保存期間、削除条件、圧縮方針、月額コスト分類を扱う。

駅構内図、駅設備、商業施設トイレ情報、号車情報は公式情報を正にする。ユーザー投稿は公式情報の上書きではなく、現地補足、写真ステップ、迷いやすさ、混雑、清潔度、閉鎖/満室などの実体験として扱う。外部候補データは、公式情報、施設/鉄道事業者/自治体/商業施設オーナー提供、運営確認、ログイン済みユーザー投稿、軽量ゲスト状態投稿より低い信頼度として扱う。

初期は日本全国/全世界の全量取り込みをしない。日本国内の対象駅、路線、エリア単位で段階投入し、公開テーブルに直接入れる前に候補ステージングで重複統合と信頼度判定を行う。公式構内図画像や商業施設マップは、権利確認なしに保存せず、公式URL、確認日、要約された構造データを持つ。
初期データ投入は、関東の主要駅/空港/駅周辺を主対象にし、関東以外は大阪・福岡の空港/主要駅ハブに限定する。その他地域は地点提案、投稿募集候補、支援者分布、利用ログを見て追加する。

問い合わせはメール、フォーム、管理画面で受け付ける。AIは分類、優先度付け、類似回答検索、返信下書きに使うが、送信前に人間が確認する。回答は、カテゴリ、質問要約、標準回答、根拠、承認者、再利用可否、最終確認日を持つナレッジとして蓄積する。個人情報、個別契約条件、返金、法務、BAN、削除判断を含む回答は自動再利用しない。

## 広告/スポンサー実装原則

- トイレ安全情報・最短案内より広告を上に出さない
- 緊急時モードでは広告カード、バナー、全画面広告を出さず、実用的な導線目印だけ小さく表示できる
- 通常検索/駅攻略ではスポンサー目印、エリアスポンサー、関連店舗カードを表示できる
- トイレ詳細/ルート閲覧では「このルートの目印」「近くの特典」として、トイレ安全情報より下に表示する
- 投稿後はスポンサーコード、SNS共有カード、称号、協賛表示を出せる
- SNS共有カードは広告なしカードとスポンサー付きカードをユーザー選択式にする
- `Sponsored` / `PR` 表記を明確にする
- 広告と安心度評価・清潔度・ランキングを混ぜない
- 最初はスポンサー枠を運営が手入力で管理する
- 効果測定はコード表示数を主指標、タップ数を補助指標、自己申告利用数を成果推定、店舗報告を任意の補助指標にする
- 掲載料・広告料はプラン種別×掲載期間で一律算出する
- 海外向けは地域別価格表で通貨、税、決済手数料を調整する

## 掲載プラン/法務/承認

初期掲載プランは国内向け税別JPYで、Free Claim 0円、Official Lite 5,000円/月、Route Marker 15,000円/月、Area Sponsor 50,000円/月、Campaign Spot 30,000円/2週間を使う。期間単位は1ヶ月、3ヶ月、6ヶ月、12ヶ月を基本にし、キャンペーンは2週間単位にする。

海外価格はMVPでは出さない。ただし、価格データは `country_code`、`currency`、`tax_included`、`plan_code`、`billing_period`、`price_amount`、`region_price_tier`、`active_from`、`active_to` を扱える前提にする。初期は JP / JPY / 税別 のみ有効化する。

公開前に用意する法務成果物:
- 利用規約
- プライバシーポリシー
- 投稿/撮影ガイドライン
- 広告/スポンサー表示ポリシー
- 店舗/スポンサー掲載規約
- 特商法表記/販売条件ページ
- クラウドファンディング支援者情報管理ルール

ユーザー承認は、アカウント作成時の利用規約/プライバシーポリシー同意に加え、位置情報、投稿、写真、トイレ内写真、SNS共有、スポンサー付き共有カード、支援者名掲載で必要に応じて個別確認を出す。承認ログとして、規約バージョン、同意種別、同意日時、ユーザーIDまたは端末識別子、同意画面、撤回状態を保存する。

支援者リターンは、リターン提供に必要な最小情報だけを扱う。共通で扱う情報は支援者ID、リターン種別、支援ステータス、連絡用メール、支援者コード、同意状態、提供状態、削除/変更依頼状態とする。名前掲載、店舗/施設掲載、公式スポンサー掲載はデフォルト非公開にし、公開前プレビューと個別同意がある場合だけ公開する。クラウドファンディングCSVは取込ステージングで確認し、アプリ用の支援者権利データへ変換後、原本CSVは90日以内に削除またはアクセス制限付きアーカイブに移す。アプリ連携は支援者コードまたはメールリンクで行う。削除/変更依頼はユーザー向けには「受付済み」「対応中」「対応完了」の状態だけを表示し、具体的な期限は表示しない。運営内部では原則5営業日以内の非公開化を対応目標として管理する。

正式公開前の法務/税務レビューは、利用規約、プライバシーポリシー、投稿/撮影ガイドライン、広告/スポンサー表示ポリシー、店舗/スポンサー掲載規約、特商法表記/販売条件ページ、支援者情報管理ルール、同意画面、削除依頼フロー、掲載プラン価格表、返金/キャンセル条件をレビューパッケージ化して行う。法務は弁護士、税務/会計は税理士へ確認依頼し、指摘は管理画面またはIssueで対象文書、版、指摘内容、重要度、対応方針、対応者、再確認要否、完了日を記録する。高重要度の指摘が残っている状態では正式公開しない。

## 外部サービス費用/維持費管理

管理画面では、地図、DB、画像保存、AI画像処理、通知、ビルド/配布、決済、ホスティング、ドメイン、監視/ログの維持費を確認できるようにする。

MVP一般公開時の外部サービス月額上限は50,000円、先行ベータでは30,000円を目安にする。70%で注意、85%で警告、100%で運営者確認、120%で高コスト機能を一時制限する。ただし、緊急時の `今すぐトイレ` 体験は止めない。

MVPで最低限扱う項目:
- Google Maps Platform: 地図表示、Places、Geocoding、Routes等の料金、無料枠、API制限、商用利用条件
- Supabase: DB、Auth、Storage、Edge Functions、PostGIS、転送量、ストレージ容量
- Expo/EAS: ビルド、配布、OTA更新、利用量
- Apple Developer Program / Google Play Console: 開発者登録、テスト配布、公開
- Stripe: B2B掲載料・スポンサー枠の請求、手数料
- RevenueCat: 一般ユーザー向けアプリ内課金を入れる場合の候補
- AI画像処理: 顔検出、ぼかし、不適切画像判定、通報分類
- 通知/メール、メール送受信/問い合わせ管理、AI問い合わせ補助、LP/管理画面ホスティング、ドメイン、監視/ログ

料金や無料枠は変わるため、実装時点の公式情報を確認し、管理画面上で公式URL、確認日、契約者、請求先、月額見込み、実績、アラート閾値を登録する。

## Git管理方針

推奨:
- `main`: 常にリリース可能な安定版
- `develop`: 複数人開発になったら導入。1人開発なら省略可
- `feature/<短い機能名>`: 機能ごとの作業ブランチ
- `fix/<短い修正名>`: 不具合修正
- `release/alpha-YYYYMMDD`: 先行公開前の安定化
- tag: `v0.1.0-alpha`, `v0.2.0-beta`, `v1.0.0`

最初は複雑にしすぎず、`main` + `feature/*` + PRレビュー + tag で十分。クラウドファンディングの約束に関わるリターン機能は、issueで要件と提供状態を追跡する。

## 確定済み前提

- コア価値は「安心して使えるトイレ情報の可視化」
- 現在の重心は「駅・施設・街の安心トイレ攻略」
- 初期開発は Expo + React Native + TypeScript で iOS/Android 両対応として進める
- 初期リリース対象国は日本国内のみとする
- 初期対象エリアは関東を主対象にし、大阪・福岡は空港/主要駅ハブに絞る
- 公開順は iOS TestFlight を先行し、Android は同時期にクローズドテストを開始する
- Web/PWA は本体ではなく、LP・管理画面・スポンサー申込導線・簡易デモに限定する
- 投稿方式は写真ステップ + 選択式チップを第一候補にする
- 閲覧は匿名可。レビュー・評価・写真ステップ投稿・地点提案はログイン必須
- 軽量な一時状態投稿のみゲスト投稿可。ただし信頼スコア・称号・SNSカードには反映しない
- 一般ユーザーはログイン後に新規トイレ地点を提案できる。短時間大量登録や重複は制限し、同一建物内の複数登録は建物単位の登録セッションとして判定する
- 写真ステップ投稿は公開前自動スキャンを行い、顔だけ検出された場合は自動ぼかし後に公開する
- 人物全身、鏡、個人情報、トイレ個室内、不適切画像の疑いがある場合は確認待ちにする
- トイレ内写真を投稿する場合は、投稿前に毎回ポップ表示で注意喚起する
- 問題投稿はまず注意通知を行い、反復・悪質な場合のみ投稿制限、一時停止、BANの順に段階対応する
- 安心度は重み付けスコアにし、清潔度は強く反映しつつ独立表示する
- ネガティブ体験は警告フラグと強い減点で扱う
- 一般ユーザー動画投稿はMVPでは扱わない
- 将来は店舗・施設・テナント・スポンサー側にも価値を返す
- MVPでは施設情報修正/オーナー申請を受け付け、運営が手動確認して反映する
- 施設オーナーの公式情報編集はPhase2で簡易編集画面として提供する
- 掲載料・広告料は企業ごとの個別交渉ではなく、プラン種別×掲載期間で一律算出する
- CLEAN TOILET 認定制度は将来構想

## 禁止事項

- 医療的な診断・助言を提供しない
- 店舗・施設への誹謗中傷を放置しない
- 写真に人物・個人情報が写った投稿を放置しない
- トイレ内写真を無条件に投稿させない
- トイレ内の人物・鏡・個人情報・個室内の疑いがある写真を、ぼかしだけで公開しない
- 未確認の認定・公式評価を表示しない
- 地図や施設情報の利用規約を未確認のまま商用公開しない
- 広告で安心度・清潔度・ランキングを買わせない
- 緊急時体験を広告で阻害しない

## 公式情報確認メモ

- React Native: Android / iOS 向けに React でネイティブアプリを作れる。新規アプリでは Expo などのフレームワーク利用が推奨されている。
- Expo: JavaScript / TypeScript プロジェクトから Android / iOS / Web に展開でき、アプリストア配布やOTA更新の導線がある。
- Supabase: Postgres、Auth、Storage、Realtime、Edge Functions を提供し、Expo React Native / Flutter / Swift / Kotlin の導線がある。
- Supabase PostGIS: 近い順検索や地図表示範囲内検索に使える。
- Flutter: 単一コードベースで iOS / Android / Web / Desktop に展開できる。
- Swift: Appleプラットフォーム向けに高速・安全なコードを書けるが、Androidは別技術が必要。
- Google Maps Platform: Maps SDK、Places、Routes、Geocoding 等があり、地図・場所検索系の候補になる。
