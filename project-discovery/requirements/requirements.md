# 要件探索: CLEAN TOILET(仮)

更新日: 2026-06-21

## 背景・目的

CLEAN TOILET(仮) は、外出時にトイレの不安を抱える人が、現在地周辺検索と駅攻略を中心に「今すぐ行ける安心候補」を探し、写真ステップ式ルート、清潔度、安心度、個室数、混雑傾向、階数、男性/女性/共用/多目的の違いを確認して、迷わず行動できるようにするアプリ。

単なる場所情報ではなく、実際に行くための攻略情報を共有することが価値の中心になる。

## 参考

ユーザー入力では「CLEAN TOILET(仮) の賞状やステッカーを渡す」構想に加え、現実世界とバーチャル的なポップさを融合したSNS共有カード、称号、駅攻略、スポンサーコード、導線の目印広告の構想がある。参考画像そのものは未提供のため、UIや認定制度の具体デザインは未確定。

## 確定している要件

- 現在地から近いトイレ検索
- 駅名検索
- 初期リリース対象国は日本国内のみ
- 初期対象エリアは関東を主対象にし、大阪・福岡は空港/主要駅ハブに絞って初期拡張対象にする
- 駅構内図、駅設備、商業施設トイレ情報、号車情報は公式を正にし、投稿は補足・更新提案として扱う
- `今すぐトイレ` による最短候補・安心候補・代替候補の提示
- 商業施設はPhase1ではフル攻略対象外。ただし現在地/駅周辺の代替候補として基本表示する
- 地図上でのトイレ表示
- 写真ステップ式ルート投稿
- レビュー、評価、写真ステップ投稿、新規地点提案はログイン必須
- 閲覧は匿名可。軽量な一時状態投稿のみゲスト投稿可
- 写真ステップ投稿は公開前に自動スキャンする
- 顔だけ検出された写真は自動ぼかし後に公開し、人物全身、鏡、個人情報、トイレ個室内、不適切画像の疑いがある場合は確認待ちにする
- トイレ内写真を投稿する場合は、投稿前に毎回ポップ表示で注意喚起する
- 清潔度評価
- 安心度の可視化
- 安心度は単純平均ではなく重み付けスコアで算出し、清潔度は強く反映しつつ独立表示する
- 「入れなかった」「入ったが使えなかった」「満室だった」「怖い/不安だった」「汚すぎた」「故障/閉鎖/利用制限あり」などのネガティブ体験は警告フラグと強い減点で扱う
- 個室数、階数、改札内/外、男性/女性/共用/多目的の情報記録
- ユーザー投稿による情報蓄積
- 一般ユーザーによる新規トイレ地点提案。ただし短時間大量登録、重複、不自然な登録は制限し、管理者確認に回す
- 将来的な店舗・施設・テナント・スポンサー側メリットの設計
- 導線上の目印広告、スポンサーコード、エリア協賛の収益仮説
- 施設情報修正/オーナー申請はMVPで受け付け、運営が手動確認して反映する
- 施設オーナーの公式情報編集はPhase2で簡易編集画面として提供する
- 掲載料・広告料は企業ごとの個別交渉ではなく、プラン種別×掲載期間で一律算出する
- 初期掲載プランは国内向け税別JPYの公開価格表で運用し、海外は実運用せず将来対応できる価格構造だけ持つ
- スポンサーコードの効果測定は、コード表示数を主指標、タップ数を補助指標、自己申告利用数を成果推定、店舗報告を任意の補助指標として扱う
- スポンサー表示は導線目印・特典として扱い、緊急時は最小化、通常時/投稿後/SNS共有時に段階的に表示する
- 広告は `PR` / `Sponsored` 表記を必須にし、安心度、清潔度、ランキングには影響させない
- Google Maps Platform等の料金、無料枠、API制限、商用利用条件、公式URL、確認日、契約者、月額見込み、実績、アラート閾値を管理画面で確認できるようにする
- 写真、ぼかし後画像、原本、通報証跡、レポート、ログ等のアップロード先をデータ種別ごとに管理できるようにする
- 問い合わせはメールと管理画面で受け付け、AIが分類・優先度付け・類似回答検索・返信下書きを補助する
- 人間またはAIが作成した問い合わせ回答を、承認済み回答ナレッジとして蓄積し、次回以降の回答候補に使う
- 公開前に利用規約、プライバシーポリシー、投稿/撮影ガイドライン、広告/スポンサー表示ポリシー、店舗/スポンサー掲載規約、特商法表記/販売条件ページ、支援者情報管理ルールを用意する
- 投稿、評価、写真、地点提案、SNS共有、支援者連携など、ユーザーの権利や個人情報に関わる操作では明示同意と同意ログを残す
- CLEAN TOILET 認定制度の将来構想
- クラウドファンディング支援者向けリターンの提供
- 支援者リターンは必要最小限の個人情報で管理し、名前掲載・店舗掲載・スポンサー掲載は任意の個別同意とプレビュー確認を必須にする

## 理想形（全部入り）

- ユーザーがアプリを開いて `今すぐトイレ` を押すだけで候補が出る
- 駅・路線・改札・号車・階数から最短トイレを探せる
- 隣接する商業施設や駅ビルの代替トイレも分かる
- 写真ステップ式ルートで、文字を読まなくても迷わず行ける
- 男性/女性/共用/多目的、個室数、洗面台数、ベビー設備、オストメイト等を確認できる
- 混雑しやすい時間、満室になりやすさ、入口の分かりにくさを確認できる
- 投稿者が称号、貢献実感、SNS共有カードを得られる
- 施設やテナントが公式情報、公式ルートカード、スポンサーコード、エリア協賛を掲載できる
- 高評価施設をアプリ内やSNSで紹介できる
- CLEAN TOILET 認定を受けた施設がステッカーや賞状でPRできる
- 不適切投稿や古い情報を運営が管理できる

## MVP要件

MVPでは「ユーザーが最短で使えること」「投稿者が簡単に行き方を残せること」「企業広告価値を小さく検証できること」を最優先にする。

| 要件 | 優先度 | 理由 |
|---|---|---|
| `今すぐトイレ` で候補を出せる | MVP | 焦っているユーザーに検索条件を考えさせないため |
| 近くのトイレを検索できる | MVP | 外出中の即時ニーズ |
| 駅名で検索できる | MVP | 駅攻略・号車・改札の価値を出すため |
| 商業施設を代替候補として表示できる | MVP候補 | フル攻略は後回しにしつつ、駅周辺の逃げ道を残すため |
| 地図でトイレ位置を確認できる | MVP | 距離・方向・代替候補の判断に必要 |
| トイレ詳細を見られる | MVP | 写真ステップ、評価、階数、個室数を集約するため |
| 写真ステップ式ルートを投稿できる | MVP | 実際に行ける情報の蓄積が価値の中心 |
| 写真投稿を公開前スキャンできる | MVP | 人物・鏡・個人情報・不適切画像を公開前に止めるため |
| トイレ内写真の投稿前確認ポップを表示できる | MVP | トイレ内写真のプライバシーリスクを投稿前に明示するため |
| 選択式チップで軽量な一時状態投稿ができる | MVP | 文字入力負荷を下げ、ゲストでも最新状態を残せるようにするため |
| ログイン済みユーザーが新規トイレ地点を提案できる | MVP | 初期データ拡充に必要。ただし悪質登録や重複を管理できる状態にするため |
| 清潔度を評価できる | MVP | 安心判断の主要軸 |
| 安心度を評価できる | MVP | プロダクト固有の主要軸。単純平均ではなく重み付けスコアにする |
| ネガティブ体験を警告表示できる | MVP | 平均点に混ぜると重要な失敗体験が薄まるため |
| 個室数・種別・階数を記録できる | MVP | 満室不安や施設内トイレの違いに対応するため |
| スポンサー目印/コードを表示できる | MVP候補 | 収益仮説を早期に検証するため |
| 施設情報修正/オーナー申請を受け付けられる | MVP候補 | 誤情報を減らし、施設側の公式掲載ニーズを検証するため |
| 外部サービス費用/アップロード先を管理できる | MVP候補 | 地図・画像・AI・配布・決済の維持費を把握し、赤字化やAPI制限到達を早期に検知するため |
| 問い合わせ管理とメール設定ができる | MVP候補 | 通報、削除依頼、スポンサー相談、施設修正依頼を管理画面で扱うため |
| AI返信下書きと回答ナレッジを管理できる | MVP候補 | 問い合わせ対応を毎回ゼロから作らず、運営負荷を下げるため |
| 通報できる | MVP | 投稿型サービスの安全運用に必要 |
| 管理者が投稿を非公開にできる | MVP | 不適切投稿対応に必要 |
| 投稿者へ注意通知・投稿制限を行える | MVP | 悪質投稿には段階対応し、善意の投稿者をいきなりBANしないため |

## 施設オーナー/広告料金方針

MVPでは、施設オーナーが直接データを編集する管理画面は作らない。代わりに、施設情報修正/オーナー申請フォームを用意し、運営が確認して公式情報へ反映する。

Phase2では、施設オーナーが営業時間、設備、利用条件、公式写真、公式ルートカード、スポンサーコードを扱える簡易編集画面を提供する。Phase3では、認定制度、データレポート、複数店舗管理、請求/契約管理へ広げる。

掲載料・広告料は、企業ごとの個別交渉で変えず、プラン種別と掲載期間で一律算出する。海外展開時は地域別価格表を用意し、通貨、税、決済手数料を地域単位で調整する。

初期掲載プラン:

| プラン | 価格 | 対象 | 内容 |
|---|---:|---|---|
| Free Claim | 0円 | 施設/店舗 | 公式情報修正依頼、オーナー申請 |
| Official Lite | 5,000円/月 | 小規模店舗 | 公式情報、利用条件、スポンサーコード、簡易レポート |
| Route Marker | 15,000円/月 | 駅周辺店舗/テナント | 導線目印、ルート上PR、コード表示、表示数/タップ数 |
| Area Sponsor | 50,000円/月 | 商業施設/企業/自治体 | 駅/エリア協賛、SNSカード協賛、複数目印、月次レポート |
| Campaign Spot | 30,000円/2週間 | キャンペーン | 期間限定コード、投稿後画面、共有カード協賛 |

期間単位は1ヶ月、3ヶ月、6ヶ月、12ヶ月を基本にし、初期は長期割引を入れない。キャンペーン枠は2週間単位にする。

海外価格はMVPでは出さない。ただし将来のために、国、通貨、税込/税別、プランコード、請求期間、価格、地域価格帯、有効期間を扱える構造にする。

返金は、掲載開始前キャンセル可、掲載開始後は原則返金なしとする。運営都合で掲載できない期間は、未掲載分を返金または翌月充当する。

## スポンサー表示方針

スポンサー表示は、ユーザーの不安や緊急性を邪魔する広告ではなく、移動中に役立つ導線目印・特典として扱う。

| シーン | 表示量 | 方針 |
|---|---|---|
| 緊急時 `今すぐトイレ` | 最小 | 広告カード、バナー、全画面広告は出さない。実際に迷いにくくなる導線目印だけ小さく表示できる |
| 通常検索/駅攻略 | 中 | スポンサー目印、エリアスポンサー、関連店舗カードを表示できる |
| トイレ詳細/ルート閲覧 | 小〜中 | トイレ安全情報より下に「このルートの目印」「近くの特典」として表示する |
| 投稿後 | 中〜高 | スポンサーコード、SNS共有カード、称号、協賛表示を出せる |
| SNS共有時 | 任意 | 広告なしカードとスポンサー付きカードをユーザーが選べる |

共通ルール:
- `PR` / `Sponsored` 表記を必須にする
- 広告、スポンサー、掲載料は安心度、清潔度、ランキングに影響させない
- スポンサーコードは候補選択前に押し出さず、ルート確認後、到着後、投稿後に表示する
- アフィリエイトリンクは扱わない
- 緊急時体験を広告で阻害しない

## 駅/施設データ取得方針

駅構内図、駅設備、商業施設トイレ情報、号車情報は公式情報を正にする。
公式情報は、鉄道事業者、商業施設、自治体、施設運営者、確認済み施設オーナーの情報を優先する。
ユーザー投稿は、公式情報の上書きではなく、現地補足、写真ステップ、迷いやすさ、清潔度、混雑、閉鎖/満室などの実体験情報として扱う。

信頼順位:
1. 公式情報
2. 施設/鉄道事業者/自治体/商業施設オーナー提供
3. 運営確認
4. ログイン済みユーザー投稿
5. 軽量ゲスト状態投稿
6. 外部候補データ

海外は国、都市、データ種別ごとに精度が異なるため、一括で同品質として扱わない。
MVPでは海外データを収集・公開せず、日本国内に集中する。
将来の海外対応に備え、国、地域、言語、通貨、タイムゾーン、データ信頼度、公式ソース種別を扱える余地は残す。
GTFS/GTFS Pathways、Google Places、OpenStreetMapは将来の候補データや照合には使うが、未検証の情報は「未確認」と表示する。
データ量対策として、初期は日本全国/全世界全量ではなく、日本国内の対象駅、路線、エリア単位で段階投入する。

初期対象エリア:
- 主対象: 関東。東京都、神奈川県、千葉県、埼玉県の主要駅、空港、駅周辺を優先する
- 関東優先候補: 羽田空港、成田空港、東京、新宿、渋谷、池袋、品川、上野、横浜、大宮、千葉
- 初期拡張対象: 大阪、福岡。大阪/梅田、新大阪、なんば、関西国際空港、伊丹空港、博多、天神、福岡空港を優先候補にする
- その他地域: 全国全量投入はせず、地点提案、投稿募集候補、支援者分布、利用ログを見て段階追加する

## 問い合わせ/AI回答補助方針

MVPでは、問い合わせをメール、フォーム、管理画面で受け付ける。
AIは問い合わせの分類、優先度付け、類似回答検索、返信下書きに使う。
ただし、削除、BAN、返金、法務判断、スポンサー条件、外部公開回答は人間が最終確認する。

問い合わせ回答は、個人情報や個別条件を除いたうえで、カテゴリ、質問要約、標準回答、根拠、承認者、再利用可否、最終確認日を持つ回答ナレッジとして蓄積する。
承認済みナレッジだけを次回以降のAI回答候補に使う。

## ユーザー承認/同意方針

承認は、一括同意だけにせず、ユーザーの行動とリスクに応じて段階的に取る。

| タイミング | 承認内容 | 承認方法 |
|---|---|---|
| 初回匿名閲覧 | 利用条件、プライバシーポリシーへの導線 | 初回表示の同意バナーまたは確認モーダル |
| アカウント作成 | 利用規約、プライバシーポリシー | チェックボックス + 同意して登録 |
| 位置情報利用 | 現在地取得の目的 | OS権限の前にアプリ内説明。拒否時は駅名検索へ誘導 |
| レビュー/評価/地点提案 | 投稿規約、公開範囲、通報/非公開化 | 初回投稿前に明示同意。規約更新時は再同意 |
| 写真ステップ投稿 | 写真投稿ガイドライン、人物/個人情報/撮影禁止への注意 | 初回写真投稿前に同意 |
| トイレ内写真投稿 | トイレ内撮影の注意、人物/鏡/個人情報/個室内禁止 | 投稿前に毎回ポップ表示で確認 |
| SNS共有 | 共有内容、スポンサー付きカードの有無 | 共有前プレビューで選択・確認 |
| スポンサーコード表示 | PR/Sponsored 表記、特典条件 | コード表示画面で条件を明示 |
| 支援者連携/名前掲載 | 表示名、掲載範囲、削除依頼方法 | 明示同意。表示名は任意入力。公開前にプレビュー確認 |

同意ログとして、規約バージョン、同意種別、同意日時、ユーザーIDまたは端末識別子、同意画面、撤回状態を保存する。

## 支援者リターン/個人情報管理方針

クラウドファンディング支援者情報は、リターン提供、本人連携、問い合わせ対応、法務/会計上必要な確認に限って扱う。

| リターン | 取得する情報 | 公開/表示 | アプリ連携 |
|---|---|---|---|
| お礼メッセージ | 支援者ID、連絡用メール、リターン種別、送信状態 | 公開しない | 不要 |
| 先行利用権 | 支援者ID、連絡用メール、招待コード、利用開始状態 | 公開しない | メールリンクまたは支援者コードでアカウントへ連携 |
| 初期サポーターバッジ | 支援者ID、アプリユーザーID、バッジ種別、付与状態 | アプリ内で本人が表示/非表示を選択 | 連携後に付与 |
| 支援者名掲載 | 任意の表示名、掲載可否、掲載範囲、削除依頼状態 | 明示同意がある場合のみ公開 | 連携後に表示名を確認 |
| 店舗・施設掲載 | 店舗/施設名、所在地、公式URL、担当者連絡先、掲載可否 | 掲載前に内容確認と同意を取る | 施設情報修正/オーナー申請へ接続 |
| 公式スポンサー掲載 | 企業/団体名、担当者連絡先、掲載プラン、掲載期間、PR表記、素材 | 契約/同意後のみPR/Sponsored表記つきで公開 | スポンサー管理へ接続 |
| CLEAN TOILET認定制度への優先選考 | 施設情報、担当者連絡先、選考希望、連絡状態 | 認定確定までは公開しない | Phase2以降の認定申請へ引き継ぐ |

共通ルール:
- 住所・電話番号は物理リターンを行わない限り取得しない
- 公開名は実名ではなく任意の表示名を基本にする
- 名前掲載、店舗/施設掲載、スポンサー掲載はデフォルト非公開にし、個別同意がある場合だけ公開する
- 公開前に表示内容のプレビューを見せ、同意ログを残す
- 削除依頼フォームから掲載停止を受け付ける。ユーザー向けには「受付済み」「対応中」「対応完了」の状態だけを表示し、具体的な期限は表示しない
- 運営内部では、削除/変更依頼を原則5営業日以内に非公開化する対応目標として管理する
- アプリ連携は支援者コードまたはメールリンクで行い、連携時に利用規約、プライバシーポリシー、支援者連携への同意を確認する
- クラウドファンディングCSVは取込ステージングで確認し、アプリ用の支援者権利データへ変換する
- 原本CSVはアクセス権限を制限し、取込確認後90日以内に削除またはアーカイブする
- 会計・決済・返金確認に必要な記録は、クラウドファンディング/決済サービス側の記録と社内台帳で管理し、アプリ公開用データと分ける
- 支援者情報管理ルール、プライバシーポリシー、販売条件ページはクラウドファンディング開始前に用意し、正式公開前に法務/税務専門家レビューを行う

## 公開前の法務/税務レビュー方針

公開前レビューは、相談メモだけで終わらせず、対象文書、画面、同意導線、価格/返金条件をまとめたレビューパッケージを作成して行う。

レビュー対象:
- 法務: 利用規約、プライバシーポリシー、投稿/撮影ガイドライン、広告/スポンサー表示ポリシー、店舗/スポンサー掲載規約、特商法表記/販売条件ページ、支援者情報管理ルール、同意画面、削除依頼フロー
- 税務/会計: クラウドファンディング支援金とリターン、掲載料/広告料、消費税、税込/税別表記、請求書/領収書、インボイス対応、返金/キャンセル、Stripe等の決済記録、海外対応を見据えた通貨/税区分

レビュー手順:
1. レビュー対象文書に版番号と更新日を付ける
2. 弁護士へ法務レビュー、税理士へ税務/会計レビューを依頼する
3. 指摘は管理画面またはIssueで、対象文書、版、指摘内容、重要度、対応方針、対応者、再確認要否、完了日を記録する
4. 高重要度の指摘は正式公開前に修正し、必要に応じて再レビューを受ける
5. レビュー完了後、レビュー実施日、確認者、対象版、未解決リスクを公開前チェックとして残す

## 外部サービス費用/アップロード先管理方針

Google Maps Platform等の料金・無料枠・API制限・商用利用条件は変更される可能性があるため、要件定義書に固定値として閉じ込めず、管理画面で公式URLと確認日つきで管理する。

管理対象は少なくとも以下にする。

- Google Maps Platform: 地図表示、Places、Geocoding、Routes等
- Supabase: DB、Auth、Storage、Edge Functions、PostGIS
- Expo/EAS: ビルド、配布、OTA更新
- Apple Developer Program / Google Play Console: アプリ公開・テスト配布
- Stripe: B2B掲載料、スポンサー枠、請求
- RevenueCat: 一般ユーザー向けアプリ内課金を導入する場合の候補
- AI画像処理: 顔検出、ぼかし、不適切画像判定、通報分類
- 通知、メール、メール送受信/問い合わせ管理、AI問い合わせ補助、ドメイン、LP/管理画面ホスティング、監視/ログ

アップロード先は、写真ステップ、トイレ内写真、自動ぼかし後画像、原本保管、通報証跡、レポート、ログを分けて扱う。公開画像と非公開証跡を同じ扱いにせず、保存期間、削除条件、圧縮方針、公開範囲、コスト分類を管理できるようにする。

## 地点提案の判定方針

一般ユーザーはログイン後、新規トイレ地点を提案できる。公開データとして扱う前に、重複、建物、階数、種別、投稿者の過去実績、短時間登録数を見て判定する。

- 同一建物内で複数階・男女別・多目的などを連続登録するケースは正常行動として扱う
- 同一建物内の連続登録は「建物単位の登録セッション」としてまとめ、階数・種別・位置関係が整っているかを見る
- 短時間に別エリアへ多数登録する、同じ地点を重複登録する、写真や階層情報が極端に不足する場合は制限または管理者確認に回す
- ゲスト投稿は新規地点提案には使えない

## 写真投稿・トイレ内写真の扱い

MVPでは、写真投稿の中心を「トイレまでの導線」「入口」「案内板」「フロア上の目印」に置く。トイレ内写真は必須にしない。

- 写真ステップ投稿は、アップロード後に公開前自動スキャンを行う
- 顔だけ検出された場合は自動ぼかし後に公開する
- 人物全身、鏡、個人情報、トイレ個室内、不適切画像の疑いがある場合は確認待ちにする
- トイレ内写真が含まれる場合は、投稿前に毎回ポップ表示で注意喚起する
- ポップでは、人物、鏡越しの映り込み、個人情報、私物、撮影禁止表示、利用中の個室が写っていないことを確認させる
- 駅や施設までの道のりで避けにくく人物が写っただけの投稿は、ぼかしや保留の対象にはしても、注意・違反カウントの対象にはしない
- トイレ内で人物・鏡・個人情報・個室内の疑いがある写真は、公開せず確認待ちまたは非公開にする
- 問題投稿が確認された場合は、まず投稿者へ注意通知を行い、反復・悪質な場合に投稿制限、一時停止、BANの順に段階対応する

## 安心度の算出方針

安心度は単純平均ではなく、複数要素の重み付けスコアとして扱う。清潔度は需要が強いため安心度へ強めに反映するが、安心度に吸収せず、清潔度単体でも必ず表示する。

MVP時点の仮配分:

| 要素 | 役割 | 重みの目安 |
|---|---|---|
| 清潔度 | 安心判断の中心 | 35% |
| 入りやすさ | 入れる雰囲気、入口の分かりやすさ | 20% |
| 使えた実績 | 実際に利用できたか | 20% |
| 導線の分かりやすさ | 写真ステップや迷いにくさ | 15% |
| 混雑しにくさ | 満室不安の低さ | 10% |

ネガティブ体験は平均に混ぜて薄めず、警告フラグと強い減点として扱う。

- 入れなかった
- 入ったが使えなかった
- 満室だった
- 怖い/不安だった
- 汚すぎた
- 故障/閉鎖
- 利用制限あり

表示では、安心度スコア、清潔度、注意フラグを分けて見せる。
