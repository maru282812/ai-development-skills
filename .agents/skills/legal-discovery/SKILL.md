# Purpose

このスキルは **「どの法律が適用されるかを調べるスキルではない」**。目的は、サービスを **公開・運営・課金・個人情報管理** するために必要な **法務成果物（ドキュメント）を発見する** こと。

実務で本当に必要なのは法律知識そのものではなく、次のような **成果物** であることがほとんど：

- 利用規約 / プライバシーポリシー / 特定商取引法に基づく表記
- 利用同意（オプトイン）/ Cookie 同意
- キャンセルポリシー / 返金ポリシー / データ削除ポリシー
- （契約系: NDA / 業務委託契約 / SaaS契約 → 詳細は [[contract-discovery]] へ）

つまり legal-discovery は **「何の法務成果物が必要か」を決める工程**。これにより「公開直前に特商法表記が無い」「個人情報を取得しているのにプライバシーポリシーが無い」といった手戻りを防ぐ。

[[project-discovery]] の Phase7 を担う。**実務上の依存順は `requirements-discovery → data-discovery → [[contract-discovery]] → legal-discovery → [[scope-discovery]]`**（誰と何を契約するか・どんなデータを扱うかが決まらないと、必要な法務成果物が確定しないため）。Phase 番号上は Legal が先行するが、[[data-discovery]] / [[contract-discovery]] の成果が出た後に [差し戻しループ](#差し戻しループ再入可能性) で更新する前提で進める。

# 基本方針

- **AIは法的助言を断定しない**（[重要原則](#重要原則ai は法的助言を断定しない)）。「必要 / 不要 / 要専門確認」の **判定候補** を出し、断定が必要な箇所は弁護士・専門家レビューへ回す。
- 法律名の列挙で終わらせない。**成果物（ドキュメント）に落とす**ことがこのスキルの仕事。
- 1サイクル＝1テーマ。複数の発見対象を同時に質問しない（[深掘り質問ルール](#深掘り質問ルール)）。深掘りの1問は [[discovery-planner]] が作る。
- 個人情報そのものの抽出はしない（[[data-discovery]] の責務）。その結果を **入力として参照** し、法務成果物の要否に変換する。
- 契約書そのものの発見は [[contract-discovery]] に委譲する。ここでは「契約形態があるか」の有無だけ拾い、必要成果物としてリンクする。
- 不明点を勝手に確定しない。`decisions.md` に **保留 / 仮置き(assumption)** として登録する（[意思決定の記録](#意思決定の記録)）。
- 既存コード / DB / API / UI / 公開済み規約には一切変更を加えない（探索と文書化のみ）。

# 重要原則: AIは法的助言を断定しない

法務は誤りが事故に直結する。このスキルは **法的助言を提供しない**。

- 出力は **「この種類の成果物が必要そう / 不要そう / 要専門確認」という発見** であり、法的結論ではない。
- 「この内容で法的に問題ない」と **断定しない**。条文解釈・適法性判断は弁護士の領域。
- 各成果物に **`要専門家レビュー` フラグ** を付けられるようにする（特に決済・医療・未成年・個人情報の越境移転）。
- 判断材料が足りない場合は捏造せず `legal/legal-open-questions.md` と `decisions.md` に積む。
- `decisions.md` には到達時に「Legal は成果物発見まで。適法性は未判断（要専門確認）」を明記する。

# 入力

- `requirements/requirements.md`（[[requirements-discovery]] の成果物 / 機能・利用者）
- `data/data.md`（[[data-discovery]] / **PII・取得データ・保持期間・削除・所有権・エクスポート要否** → 法務成果物の前提）
- `business/business-model.md`（[[business-discovery]] / 課金方式・決済 → 特商法・返金）
- `contract/contract-inventory.md`（[[contract-discovery]] / 契約形態 → 規約・NDA・委託契約の要否）
- `integration/integration.md`（[[integration-discovery]] / 外部サービス → 第三者提供・委託の前提）
- `decisions.md` / `open-questions.md`（[[project-discovery]] の決定・未確定ログ）

> 未実装・未着手フェーズの入力が無い場合は、その前提を `assumption` として置き、`legal/legal-open-questions.md` と `open-questions.md` に積む。捏造しない。

# 出力

- `legal/legal.md` … 必要な法務成果物一覧（このフェーズの主成果物。旧 `legal-checklist.md` を発展）
- `legal/legal-risk.md` … 法務リスク一覧
- `legal/legal-open-questions.md` … 法務未確定事項（横断 `open-questions.md` と同期）

# 発見対象

各対象は **「この事実があるから、この法務成果物が必要になる」** という形で成果物に結びつける。

## 1. サービス提供形態
Webサービス / SaaS / マッチング / EC / サブスク / LP / LINE / モバイルアプリ / オフライン店舗。
→ 規約の必要性・アプリストア審査要件・特商法該当の起点。

## 2. 利用者区分
一般消費者 / 事業者 / 法人 / 未成年 / 医療利用者 / 学生 / 保護者。
→ 消費者保護・**未成年の同意（親権者同意）**・BtoB か BtoC かで規約構成が変わる。

## 3. 取得データ（[[data-discovery]] を参照）
氏名 / メール / 電話番号 / 住所 / 決済情報 / 医療情報 / 位置情報 / 写真 / 音声 / その他。
→ プライバシーポリシー・同意取得・要配慮個人情報の扱い。**抽出は data-discovery、要否変換はここ。**

## 4. 外部サービス
Stripe / Supabase / OpenAI / Google / LINE / AWS など。
→ 第三者提供・**委託先の管理**・データ処理（DPA）・越境移転の論点。

## 5. 課金方式
買い切り / サブスク / 従量課金 / 手数料。
→ **特商法表記**・**返金ポリシー**・**キャンセルポリシー**・自動更新の説明義務。

## 6. ユーザー投稿
コメント / 画像投稿 / レビュー / チャット。
→ 投稿ガイドライン・権利侵害対応・削除/通報フロー・著作権の取り扱い。

## 7. コンテンツ権利
誰が著作権を持つか / 生成AI成果物の扱い / 退会後の扱い。
→ ライセンス条項・**生成AI成果物の権利と免責**・退会後の権利関係。

## 8. データ保持（[[data-discovery]] を参照）
保持期間 / 削除方法 / エクスポート。
→ **データ削除ポリシー**・保持期間の開示・データポータビリティ対応。

## 9. 契約形態
利用規約のみ / 個別契約あり / NDAあり / 業務委託あり / SaaS契約あり。
→ 契約書そのものの発見は [[contract-discovery]] へ。ここでは **有無の確認と成果物リンク** のみ。

## 10. 業界規制
医療 / 動物病院 / 人材 / 金融 / 教育 / 不動産 など。
→ 業法・広告規制（例: 医療広告ガイドライン）・業界固有の表示義務。**要専門家レビュー** になりやすい。

## 11. 管轄・準拠法【補完】
利用者・事業者の所在（国内のみ / 海外含む）、準拠法・裁判管轄。
→ **GDPR / CCPA 等の越境法令** の該当可否。海外利用者がいる場合は要専門確認フラグ。

## 12. 同意取得方法【補完】
オプトイン / 利用規約同意のチェック / Cookie 同意バナー / 未成年の親権者同意。
→ 同意取得の **UI 導線**（[[screen-design-architect]] へ）と同意ログ保存（[[data-discovery]] へ）の前提。

## 13. 成果物のステータス・流用可否【補完】
各成果物について「新規作成 / 既存テンプレ流用 / 既存を改訂」、ドラフトの有無、公開先（フッター / 登録画面 / 専用ページ）。
→ [[scope-discovery]] で MVP に必要な成果物の線引きに使う。

# 進め方（Discovery ループ）

```text
入力整理（data/data.md / business/business-model.md / contract/contract-inventory.md を参照）
 → [[discovery-planner]]: 次に発見すべき1テーマに絞って質問（1テーマ1問）
 → ユーザー回答（必ず停止して確認）
 → legal/legal.md / legal/legal-risk.md を更新 / decisions.md に決定・保留・仮置きを記録
 → 法的断定が要る箇所は「要専門家レビュー」フラグを立て legal/legal-open-questions.md へ
 → Phase完了判定（確信度つき）
 → 全対象カバー後 [[discovery-auditor]] へ（横断監査・矛盾検出）
 → 差し戻し or 後続フェーズへ引き渡し
```

## 深掘り質問ルール

1回で1テーマのみ。複数の発見対象を同時に質問しない。

- 悪い例: 「課金は？ 未成年は使う？ 海外利用者は？ 投稿機能は？」
- 良い例: 「課金方式は買い切り / サブスク / 従量 / 手数料のどれですか？（特商法・返金の要否を判定するため）」

各回答は **必要 / 不要 / 後で / 未定 / コメント** で返せる形にする（[[requirements-discovery]] と同じ回答様式）。

# 意思決定の記録

発見した各成果物の要否は `decisions.md` に区分して記録する（[[project-discovery]] の決定ログ機構）。

- **決定(decision)**: ユーザーが確定した要否（例: 「特商法表記は必要」）。
- **保留(pending)**: 決める必要があるが未決 → `legal/legal-open-questions.md` / `open-questions.md` へ。
- **仮置き(assumption)**: AI/暫定で置いた前提。**確定ではない**。下流（scope / 実装 / 専門家レビュー）へ渡る前に必ず昇格 or 解消する。
- **要専門家レビュー**: 適法性の断定が必要な項目。決定ではなく「専門家へ回す」マーカー。

# 差し戻しループ（再入可能性）

このフェーズの発見は前段・後段を更新する。検出したら該当 `decisions.md` を更新し、影響フェーズを再オープンする。

- [[data-discovery]] で **新たな PII / 越境移転** を発見 → 本フェーズを差し戻し（プライバシーポリシー・同意の更新）
- [[business-discovery]] で **課金方式が変更** → 特商法・返金・キャンセルポリシーを更新
- [[contract-discovery]] で **委託・NDA が確定** → 委託先管理・第三者提供の条項要否を更新
- 同意取得が必要と判明 → [[screen-design-architect]]（同意UI）と [[data-discovery]]（同意ログ）を差し戻し
- MVP の線引きが変わる → [[scope-discovery]] を更新

# 禁止事項

- 適法性・条文解釈の **断定**（弁護士の領域 / 「要専門家レビュー」で回す）
- 契約書本文の起案・契約条件の確定（[[contract-discovery]] / 専門家の領域）
- 個人情報そのものの抽出・分類（[[data-discovery]] の責務）
- 既存規約・ポリシー・コード・UI への変更

このスキルは **必要な法務成果物の発見** に徹する。

# 完了条件

以下が説明できる状態になったら完了（[Phase完了判定](#phase完了判定)を出す）。

- どの法務成果物が **必要 / 不要 / 要専門確認** か（`legal/legal.md`）
- それぞれ **なぜ必要か**（紐づく発見対象）と **優先度**
- 主要な法務リスクが列挙されているか（`legal/legal-risk.md`）
- 未確定・要専門家レビュー事項が積まれているか（`legal/legal-open-questions.md`）

不明点が残る場合は `decisions.md` に保留 / 仮置きとして登録する。未昇格の仮置き・未解消の「要専門家レビュー」が残る間は「完了」にしない（ユーザーが明示的に暫定通過を承認した場合のみ例外、その旨を記録）。

## Phase完了判定

```text
## Phase完了判定: Phase7 Legal Discovery
- 発見対象カバー率: <x/y>
- 必要成果物の確定: <確定数 / 全候補数>
- 要専門家レビュー: <件数>（未解消）
- 未解消の保留: <件数>
- 未昇格の仮置き(assumption): <件数>
- 確信度: 高 / 中 / 低
- 判定: 完了 / 継続 / 差し戻し（→ どのPhaseへ）
```

# セルフチェック

- 法律名の列挙で終わらず、**必要な法務成果物（ドキュメント）** に落としたか

- 適法性を **断定していないか**（断定が要る箇所に `要専門家レビュー` を付けたか）
- 個人情報を自分で抽出せず、[[data-discovery]] の結果を参照したか
- 契約書本文に踏み込まず、[[contract-discovery]] にリンクしたか
- 1テーマ1問になっているか（複数の発見対象を同時に質問していないか）
- 課金・未成年・越境移転・投稿・業界規制 の論点を飛ばしていないか
- 未確定を `decisions.md` / `legal/legal-open-questions.md` に保留 / 仮置きとして登録したか（勝手に確定していないか）
- 後段の発見で前段（data/business/contract/screen）を差し戻したか
- 後続フェーズへ「全部」でなく必要情報だけ抽出して渡したか
- 既存規約・ポリシー・コード・UI に変更を加えていないか

# 実行モデルティア

推奨ティア: **deep**（判断・設計・監査の質がモデルの推論力に依存する）。
