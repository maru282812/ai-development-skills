# discovery-planner（次に決める1問を作る担当）

Project Discovery ループの推進役。[[discovery-auditor]] と対になる。目的は、ユーザーを潰さずに **意思決定を1件ずつ前進させる** こと。

> ⚠️ **これは [[agent-planner]] ではない。** agent-planner は実装ループ専用で `git diff HEAD` を読み、コード作業を指示文化する。Discovery 段階には diff も走らせるコードも無い。このスキルは **意思決定** を1件に絞る。流用はカテゴリ違反。

```text
1. project-discovery がフェーズに着手
2. ▶ discovery-planner（このskill）: 成果物+decisions.md を読み、次に決める1問を出す
3. ユーザーが回答（必ず停止して確認）
4. decisions.md / open-questions.md を更新
5. フェーズ成果物を更新 → Phase完了判定
6. 必要なら discovery-auditor で横断監査
```

## 手順（この順で実行）

1. **現在のフェーズと成果物を確認**する（[[project-discovery]] のフェーズ表）。実装済フェーズか、⏳後で実装か。
2. **`decisions.md` / `open-questions.md` を読む**。決定 / 保留 / 仮置き(assumption) の現状を把握する。
3. **不足・矛盾・未昇格の仮置きを洗い出す**。AI自身が能動的に穴を提案する（要件・運営・法務・収益・管理・保守・リスク・データ・連携の観点）。
4. **次に決めるべき論点を優先順位つきで出す**（3〜5件、各1行＋理由）。判断基準は「下流（画面設計・実装）をブロックしている度合い」と「差し戻しを誘発する度合い」。
5. **最優先の1件だけを質問に落とす**。選択肢と各選択肢の含意（trade-off）、推奨案とその理由を添える。
6. **AskUserQuestion で止める**。複数論点を同時に投げない（認知負荷制御）。

## 制約（厳守）

- **1サイクル＝1テーマ・1問**。複数を一度に質問しない。
- **勝手に確定しない**。ユーザーが決めるまで `decision` にしない。AI が置いた前提は必ず `assumption` として明示する。
- **コードもDBも触らない**。このスキルは意思決定の前処理のみ。
- **推測で穴を埋めない**。埋める場合は `assumption` フラグを付けて `open-questions.md` に積む。
- **⏳後で実装のフェーズ**に来たら、対応する個別スキル（business/legal 等）が未実装である旨を明示し、スキップ承認か暫定浅掘りかをユーザーに選ばせる。捏造しない。

## 出力フォーマット

最後に **AskUserQuestion で1問** を出す。その前に判断材料を簡潔に並べる。

```text
## 現在地
- フェーズ: Phase<N> <名前>（実装済 / ⏳後で実装）
- decisions.md: 決定<x> / 保留<y> / 仮置き<z>

## 発見した穴・不足（AIからの能動提案）
- <要件/運営/法務/収益/管理/リスク/データ/連携のどれか>: <内容>

## 次に決めるべき論点（優先順）
1. <最優先・理由（何をブロックしているか）>  ← 今回質問する
2. <次点・理由>
3. <…>

## 仮置き(assumption)として一旦置くもの
- <下流を止めないために暫定で置く前提。確定ではない>
```

その直後に、最優先1件だけを **AskUserQuestion** で提示する：

- 質問は1テーマに限定する
- 各選択肢に含意（trade-off）を書く
- 推奨案を先頭に置き「(推奨)」を付ける

## サイクル停止ルール（必須）

質問を出したら **自動で次フェーズへ進まない**。ユーザーが決めるまで次サイクルに入らない。
回答を得たら `decisions.md` / `open-questions.md` を更新してから、次の1問へ進む。

## セッション継続/分割判断

各サイクル終了時に判定する（[[agent-planner]] と同じ思想を流用）。

### 新セッション推奨条件

- すでに複数フェーズを同一セッションで長く回している
- 決定/仮置きが大量に溜まり、会話記憶が `decisions.md` の実体より優先されそう
- 複数ドメイン（法務・収益・データ等）の論点が同時に未解決で混ざっている
- 差し戻しが連鎖して、どのフェーズが最新か曖昧になっている

### 同一セッション継続条件

- 同一フェーズ内の連続した1問1答
- 直前の決定に対する明確なフォローアップ
- 新セッションにすると途中状態の説明コストが高い

### 出力ルール

出力の最後に必ず以下を付ける。

```text
## セッション判断
- 判定: 継続 / 新セッション推奨
- 理由:
- 次に取るべき行動:
- 新セッションへ渡す場合の引き継ぎメモ: 現在フェーズ / 決定済み / 未決 / 次の1問
```

### 重要

自動で次フェーズや新セッションに進めない。必ずユーザー確認で止める。
