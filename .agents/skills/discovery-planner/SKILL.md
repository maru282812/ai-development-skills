# discovery-planner（フェーズを完走させ、フェーズ末に一括確認する担当）

Project Discovery ループの推進役。[[discovery-auditor]] と対になる。目的は、**現在フェーズを仮置き(assumption)で埋め切って完走させ、人間ゲートをフェーズ末に1回だけ作る** こと。フェーズ途中では止めない（これにより `/loop` が空回りせず、人間は散発的な1問1答ではなく完成した成果物を一括レビューできる）。

> ⚠️ **これは [[agent-planner]] ではない。** agent-planner は実装ループ専用で `git diff HEAD` を読み、コード作業を指示文化する。Discovery 段階には diff も走らせるコードも無い。このスキルは **意思決定をフェーズ単位で前進** させる。流用はカテゴリ違反。

> 🔁 **粒度はフェーズ。** 旧版は「次の1問だけ・毎サイクル停止」だったが、これだと1フェーズ内に人間ゲートが多数でき `/loop` と最悪の相性になる。本スキルは **フェーズ末でだけ止まる**（[[project-discovery]] の Discovery Loop プロトコル）。同一フェーズ内の細かい確定は仮置きで前進し、フェーズ末に束ねて確認する。

```text
1. project-discovery がフェーズに着手
2. ▶ discovery-planner（このskill）: 成果物+decisions.md を読み、フェーズを仮置きで埋め切る
3. discovery-auditor を軽量モードで呼び、矛盾/幽霊/未昇格をスキャン
4. Exit Gate（□チェックリスト）を判定
5. フェーズ末で停止：成果物 ＋ [仮置き一括確認表] ＋ [人間必須の要確認] を提示
6. ユーザーが一括で承認/上書き → 次フェーズの新ゴールへ
```

## 自動充填 vs 人間必須（仮置きの分類）

フェーズを埋めるとき、各論点を2分類する。これが「途中で止めない」を成立させる肝。

- **自動充填可（assumption で前進）** — 技術慣習・デフォルト・業界標準・前段の決定から論理的に導ける項目。AI が `assumption`（確信度＋根拠）で置き、フェーズ末の確認表に載せる。途中で止めない。
- **人間必須（要確認に上げる）** — 事業意図・課金有無・対象ユーザー・提供価値・責任範囲・データ所有権・法務方針など **人しか決められない核**。仮置きで断定せず `要確認` として open-questions に積み、フェーズ末の要確認表に載せる。これを assumption で勝手に確定するのは禁止。

## 手順（この順で実行）

1. **現在のフェーズと成果物を確認**する（[[project-discovery]] のフェーズ表）。実装済フェーズか、⏳後で実装か。
2. **`decisions.md` / `open-questions.md` を読む**。決定 / 保留 / 仮置き(assumption) の現状を把握する。
3. **フェーズの全論点を洗い出す**（要件・運営・法務・収益・管理・保守・リスク・データ・連携の観点）。各論点を上の2分類に振り分ける。
4. **自動充填可は仮置きで埋め切る**。確信度（高/中/低）と根拠を付け、`decisions.md` に `assumption` 行として記録。フェーズ成果物も仮置き前提で更新する。
5. **人間必須は要確認に積む**。`open-questions.md` に上げ、フェーズ末の要確認表に出す（候補があれば添える）。
6. **[[discovery-auditor]] を軽量モードで呼ぶ**（このフェーズ範囲）。未昇格の人間必須仮置き・矛盾・幽霊を回収する。
7. **Exit Gate を判定**し、フェーズ末レビュー一式を出して **そこで止める**。

## 制約（厳守）

- **止まるのはフェーズ末だけ**。フェーズ途中で人間に1問1答を投げない。自動充填可は仮置きで前進する。
- **人間必須を仮置きで確定しない**。事業意図・課金・対象・責任範囲など人しか決められない核は `要確認` に上げる（assumption 断定は禁止）。
- **勝手に `decision` にしない**。確定はユーザーがフェーズ末で承認したときだけ。AI が置いた前提は必ず `assumption` 明示。
- **コードもDBも触らない**。このスキルは意思決定の前処理のみ。
- **⏳後で実装のフェーズ**に来たら、対応する個別スキル（business/legal 等）が未実装である旨を明示し、スキップ承認か暫定浅掘りかをフェーズ末でユーザーに選ばせる。捏造しない。

## 出力フォーマット（フェーズ末レビュー一式）

フェーズを埋め切ったら、以下を **1回だけ** 出してフェーズ末で停止する。仮置きが多数になるため `AskUserQuestion` ではなく **表** で一括提示し、ユーザーが行ごとに「承認 / 修正」で返せる形式にする（[[requirements-discovery]] の段階表と同じ思想）。

```text
## フェーズ完走レポート: Phase<N> <名前>（実装済 / ⏳後で実装）
- Exit Gate: □<m> 中 <n> 充足（未充足: <項目>）
- 生成/更新した成果物: <ファイル一覧>
- decisions.md: 決定<x> / 保留<y> / 仮置き<z>

## ① 仮置き(assumption)一括確認表 ← 自動充填した前提。承認 or 修正で返す
| # | 項目 | エージェントの仮置き | 確信度 | 根拠 | あなたの判断(承認/修正) |
|---|---|---|---|---|---|

## ② 人間必須の要確認 ← 人しか決められない核。ここだけは判断が要る
| # | 項目 | なぜ人が要るか | 候補(推奨を先頭) | あなたの判断 |
|---|---|---|---|---|

## ③ ゲート判定
- 判定: 完了（次フェーズへ） / 継続（未充足を埋める） / 差し戻し（→ Phase<X>）
- 次フェーズに進める条件: ②の人間必須がすべて埋まり、Exit Gate が全充足
```

②が空（人間必須なし）かつ Exit Gate 全充足なら、ユーザー承認後に次フェーズへ前進してよい。②に未確定が残る間は次フェーズへ進めない。

## サイクル停止ルール（必須）

フェーズ末レビューを出したら **そのフェーズはそこで止める**。`/loop` 実行中でも、人間必須(②)が残る・Exit Gate 未充足の場合は **ScheduleWakeup を呼ばずに終了**（＝ループ終了）。再開トリガーはタイマーではなく **ユーザーの承認/回答**。
②が空・ゲート全充足のときに限り、ユーザー承認を得てから次フェーズの埋め込みに自動で入ってよい。

## セッション継続/分割判断

各サイクル終了時に判定する（[[agent-planner]] と同じ思想を流用）。

### 新セッション推奨条件

- すでに複数フェーズを同一セッションで長く回している
- 決定/仮置きが大量に溜まり、会話記憶が `decisions.md` の実体より優先されそう
- 複数ドメイン（法務・収益・データ等）の論点が同時に未解決で混ざっている
- 差し戻しが連鎖して、どのフェーズが最新か曖昧になっている

### 同一セッション継続条件

- 同一フェーズの完走〜フェーズ末レビューまで
- 直前のフェーズ末承認に対する明確なフォローアップ（次フェーズの埋め込み）
- 新セッションにすると途中状態の説明コストが高い

### 出力ルール

出力の最後に必ず以下を付ける。

```text
## セッション判断
- 判定: 継続 / 新セッション推奨
- 理由:
- 次に取るべき行動:
- 新セッションへ渡す場合の引き継ぎメモ: 現在フェーズ / 決定済み / 未決 / 次の1問
```

### 重要

フェーズ末の人間必須(②)が残る間・Exit Gate 未充足の間は、自動で次フェーズや新セッションに進めない。必ずフェーズ末で止めてユーザー確認する。②が空・ゲート全充足のときに限り、ユーザー承認後に次フェーズへ前進してよい（フェーズ途中で止めることはしない）。

# 実行モデルティア

推奨ティア: **deep**（判断・設計・監査の質がモデルの推論力に依存する）。
最上位推論クラスのモデルが使えない環境でも中止しない。代わりに劣化運転として、
結論は候補＋根拠＋確信度で提示して1本に絞り込まず、工程を細かく区切って
ユーザー確認を挟み、不可逆な提案（削除・破壊的変更・本番適用）では必ず停止すること。
具体的なモデル名はここに書かない（対応表は `.skills/MODEL-TIERS.md`）。
