# Purpose

このスキルは **法務文書・契約書を作成するスキルではない**。目的は、サービス提供後のトラブル（言った言わない・スコープ外要求・返金紛争・責任の押し付け合い・データ持ち出し）を防ぐために、**合意形成に必要な契約条件と契約相手を発見・整理する**こと。

実装を曖昧なまま進めることは禁止。次の2軸を明確化する。

- **A軸: 誰と契約するか（契約インベントリ）** — 顧客 / パートナー / 外部委託 / データ委託
- **B軸: 何を・どの条件で取り決めるか（契約条件）** — 提供範囲 / 提供しない範囲 / サポート / 保守運用 / SLA / 返金 / キャンセル / 責任範囲 / データ所有権 / 成果物所有権 / 契約終了

[[project-discovery]] の契約フェーズを担う。**実務上の依存順は `requirements-discovery → data-discovery → contract-discovery → legal-discovery → scope-discovery`**。「誰と何をどの条件で契約するか」が決まらないと、[[legal-discovery]] で必要な法務成果物（規約・特商法表記・委託契約条項）も確定しない。

# 基本方針

- **AIは契約条件を断定しない**（[重要原則](#重要原則ai-は契約条件を断定しない)）。発見した条件は「合意案」であり、法的拘束力ある条文・適法性の保証ではない。
- 法務文書の起案はしない。**合意形成に必要な事実と条件を発見する**ことに徹する。条文化・契約書本文は [[legal-discovery]] / 専門家の領域。
- 1サイクル＝1テーマ。複数テーマを同時に質問しない（[質問ルール](#質問ルール)）。深掘りの1問は [[discovery-planner]] が作る。
- 個人情報・データ保持期間そのものの抽出はしない（[[data-discovery]] の責務）。その結果を **入力として参照** し、データ所有権・委託・削除条件の契約条件に変換する。
- SLA・サポート体制・返金フローの **運用実態** は [[operations-discovery]] を参照し、契約上の約束（対応レベル）に変換する。
- 不明点を勝手に確定しない。`decisions.md` に **決定 / 保留 / 仮置き(assumption) / 要専門家レビュー** で登録する（[意思決定の記録](#意思決定の記録)）。
- 既存の規約・契約・コード・UI には一切変更を加えない（探索と文書化のみ）。

# 重要原則: AIは契約条件を断定しない

契約は誤りが金銭・法的事故に直結する。このスキルは **法的助言・契約条件の保証を提供しない**。

- 出力は「この条件で合意してはどうか」という **発見・整理** であり、適法性・有効性の保証ではない。
- 「この返金条件・免責条項で法的に問題ない」と **断定しない**。条項の有効性（消費者契約法・特商法・下請法等での無効化リスク）は弁護士の領域。
- 高リスク条件には **`要専門家レビュー` フラグ** を立てる（特に: 免責・賠償上限、消費者向けキャンセル/返金、下請法該当の外部委託、著作権の譲渡、個人情報の委託、未成年取引）。
- 判断材料が足りない場合は捏造せず `contract/contract-open-questions.md` と `decisions.md` に積む。
- `decisions.md` に到達時「Contract は条件発見まで。条項の有効性・適法性は未判断（要専門確認）」を明記する。

# 入力

- `requirements/requirements.md`（[[requirements-discovery]] / 機能・利用者区分・体制 → 提供範囲・サポート対象）
- `data/data.md`（[[data-discovery]] / **PII・所有権・保持期間・削除・エクスポート・システム境界** → データ所有権・データ委託・削除条件）
- `business/business-model.md`（[[business-discovery]] / 課金方式・契約単位 → 返金・キャンセル・契約期間）
- `operations/operations.md`（[[operations-discovery]] / **サポート窓口・対応時間・障害対応・返金/削除フロー** → サポート範囲・保守範囲・SLA の現実値）
- `integration/integration.md`（[[integration-discovery]] / 外部サービス依存 → 第三者障害の責任範囲・外部委託）
- `decisions.md` / `open-questions.md`（[[project-discovery]] の決定・未確定ログ）

> 未着手フェーズの入力が無い場合は、その前提を `assumption` として置き、`contract/contract-open-questions.md` と `open-questions.md` に積む。捏造しない。

# 出力

- `contract/contract.md` … 契約条件の集約（このフェーズの主成果物 / B軸）
- `contract/contract-inventory.md` … 契約相手・契約書インベントリ（A軸）
- `contract/contract-open-questions.md` … 契約未確定事項（横断 `open-questions.md` と同期）

> 条件が大きくなった項目のみ、`sla.md` / `refund-policy.md` / `ownership.md` / `liability.md` / `termination-policy.md` 等に分割してよい（過剰生成しない。MVP では `contract/contract.md` 1本に集約が原則）。

# 発見対象（A軸: 誰と契約するか）

各対象は「この相手と・この事実があるから・この契約書/条項が必要」という形でインベントリに結びつける。

## A1. 顧客との契約
利用規約 / 発注書 / 申込書 / SaaS利用契約 / SLA。BtoC か BtoB かで構成が変わる。

## A2. パートナーとの契約
NDA / 業務委託 / 共同開発 / 代理店・紹介契約。

## A3. 外部委託
デザイナー / ライター / 開発者 / 運用代行。**著作権の帰属と下請法該当**に注意（要専門家レビューになりやすい）。

## A4. データ委託
個人情報の取扱い委託 / クラウド保管（[[data-discovery]] の PII・保管先を参照）。委託先管理・DPA の要否。

# 発見対象（B軸: 何を・どの条件で取り決めるか）

各テーマで「現状把握 → 例提示 → 判断を促す → 決定を記録 → 未確定を抽出」を回す（[Discovery ループ](#進め方discovery-ループ)）。

## B1. 提供内容（提供範囲）
提供サービス / 納品物 / 提供期間 / 契約単位。
例: Webサイト制作 / SaaS提供 / システム開発 / LINE構築 / 保守契約 / コンサル。

## B2. 提供しない内容（スコープ外）
対象外作業 / 顧客責任範囲 / 外部事業者責任範囲。
例: コンテンツ作成は含まない / 広告運用は別 / 保守は別契約 / サーバー費用は顧客負担。

## B3. サポート範囲
問い合わせ方法・窓口 / サポート対象・対象外。
例: メールのみ / LINE / 電話 / 平日のみ。→ 現実値は [[operations-discovery]] を参照。

## B4. 保守運用
障害対応 / バグ修正 / セキュリティ更新 / コンテンツ更新 / 運用代行。**無償範囲 vs 有償範囲**を分ける。

## B5. SLA（対応レベル）
受付時間 / 初回回答時間 / 障害対応着手時間 / 緊急連絡手段。
例: 24時間以内回答 / 営業日3日以内 / 緊急障害は4時間以内着手。→ 約束できる現実値は [[operations-discovery]] の体制と突き合わせる。

## B6. 返金・キャンセル
返金可否・条件 / 解約条件 / キャンセル料。
例: 着手後返金不可 / 月額は当月解約不可 / 納品後返金不可。**消費者向けは無効化リスクあり → 要専門家レビュー。**

## B7. 成果物の権利
ソースコード / デザイン / ドメイン / コンテンツ / 著作権の帰属。
例: 納品後に顧客へ譲渡 / 提供者が保持 / ライセンス提供。**外部委託からの権利移転（A3）と整合させる。**

## B8. データ所有権
顧客データの所有者 / エクスポート可否 / 解約後の保持期間 / 削除ポリシー。
例: 顧客が所有 / 解約後30日保持 / CSV出力可。→ 事実は [[data-discovery]]、契約上の約束はここ。

## B9. 責任範囲
障害責任 / データ損失責任 / 第三者サービス障害 / 間接損害 / 賠償上限。
例: AWS障害は保証対象外 / 売上損失は保証しない / 提供料金上限で賠償。**免責・上限は要専門家レビュー。**

## B10. 契約終了
解約方法 / データ削除 / アカウント停止 / 引継ぎ。

# 進め方（Discovery ループ）

```text
入力整理（requirements / data / operations / business を参照）
 → [[discovery-planner]]: 次に発見すべき1テーマに絞って質問（1テーマ1問）
 → ユーザー回答（必ず停止して確認）
 → contract/contract.md / contract/contract-inventory.md を更新 / decisions.md に決定・保留・仮置きを記録
 → 高リスク条件は「要専門家レビュー」フラグを立て contract/contract-open-questions.md へ
 → Phase完了判定（確信度つき）
 → 全対象カバー後 [[discovery-auditor]] へ（横断監査・矛盾検出）
 → 差し戻し or 後続フェーズへ引き渡し
```

## 質問ルール

一度に1テーマだけ質問する。

- 悪い例: 「SLAと返金は？」「保守と著作権は？」（同時に聞かない）
- 良い例: 「公開後の保守は提供しますか？（無償範囲と有償範囲を分けるため）」

各回答は **必要 / 不要 / 後で / 未定 / コメント** で返せる形にする（兄弟スキルと同じ回答様式）。回答後に次へ進む。

# 意思決定の記録

各契約条件は `decisions.md` に区分して記録する（[[project-discovery]] の決定ログ機構）。

- **決定(decision)**: ユーザーが確定した条件（例: 「納品後返金不可」）。
- **保留(pending)**: 決める必要があるが未決 → `contract/contract-open-questions.md` / `open-questions.md` へ。
- **仮置き(assumption)**: AI/暫定で置いた前提。**確定ではない**。下流（legal / scope / 実装 / 専門家）へ渡る前に必ず昇格 or 解消する。
- **要専門家レビュー**: 有効性・適法性の断定が必要な条件（免責・賠償上限・消費者返金・著作権譲渡・下請・個人情報委託）。

# 差し戻しループ（再入可能性）

不足・矛盾を検出したら該当 `decisions.md` を更新し、影響フェーズを再オープンする。

- **scope不足**（提供内容が不明）→ [[scope-discovery]]
- **requirements不足**（機能・利用者が不明）→ [[requirements-discovery]]
- **operations不足**（運用体制が不明でSLA/サポートを約束できない）→ [[operations-discovery]]
- **data不足**（所有権・保持期間が不明でデータ所有権を決められない）→ [[data-discovery]]
- **legal必要**（規約・特商法・適法性確認が必要）→ [[legal-discovery]]

# 禁止事項

- 契約条件の **適法性・有効性の断定**（弁護士の領域 / 「要専門家レビュー」で回す）
- 契約書本文・規約条文の起案（[[legal-discovery]] / 専門家の領域）
- 個人情報・保持期間そのものの抽出・分類（[[data-discovery]] の責務）
- 既存の規約・契約・コード・UI への変更

このスキルは **合意形成に必要な契約条件・契約相手の発見** に徹する。

# 完了条件

以下が全て説明できる状態になったら完了（[Phase完了判定](#phase完了判定)を出す）。

- 提供内容 / スコープ外 / サポート範囲 / 保守範囲 / SLA / 返金条件 / キャンセル条件 / 成果物権利 / データ所有権 / 責任範囲 / 契約終了条件（B軸）
- 誰と・どの契約書が必要か（A軸 / `contract/contract-inventory.md`）
- 各条件の **なぜそうするか** と **要専門家レビューの有無**

未確定は `contract/contract-open-questions.md` / `decisions.md` に保留 / 仮置きとして登録する。未昇格の仮置き・未解消の「要専門家レビュー」が残る間は「完了」にしない（ユーザーが明示的に暫定通過を承認した場合のみ例外、その旨を記録）。

## Phase完了判定

```text
## Phase完了判定: Contract Discovery
- 発見対象カバー率: <x/y>（A軸4 + B軸10）
- 確定した条件: <確定数 / 全候補数>
- 要専門家レビュー: <件数>（未解消）
- 未解消の保留: <件数>
- 未昇格の仮置き(assumption): <件数>
- 確信度: 高 / 中 / 低
- 判定: 完了 / 継続 / 差し戻し（→ どのPhaseへ）
```

# 後続フェーズへの引き渡し

全ドキュメントを渡さず、必要情報のみ抽出して渡す。

| 引き渡し先 | 渡す情報 |
|---|---|
| [[legal-discovery]] | 契約形態の有無 / 規約・特商法・委託契約の必要シグナル / 返金・キャンセル条件 |
| [[scope-discovery]] | MVP で必須の契約条件 / 後回し可能な条件 |
| [[operations-discovery]] | 約束したSLA・サポート範囲（運用が満たせるかの逆チェック） |
| [[data-discovery]] | データ所有権・解約後保持期間・削除/エクスポート要否 |
| [[risk-discovery]] | 契約リスク（免責・賠償上限・返金紛争・委託先・著作権） |
| 専門家レビュー | `要専門家レビュー` フラグ付き条件一式 |

# セルフチェック

- 法務文書を作らず、**合意形成に必要な条件・契約相手の発見** に徹したか
- A軸（誰と・どの契約書）と B軸（何を・どの条件）の両方を埋めたか
- 各条件に「なぜそうするか（紐づく事実）」を結びつけたか
- 適法性・有効性を **断定していないか**（高リスク条件に `要専門家レビュー` を付けたか）
- データ所有権・保持を自分で決めず [[data-discovery]] を参照したか／SLA・サポートを [[operations-discovery]] の現実値と突き合わせたか
- 成果物権利（B7）と外部委託の権利移転（A3）を整合させたか
- 1テーマ1問になっているか（複数テーマを同時に質問していないか）
- 提供範囲・対象外・SLA・返金・責任範囲・契約終了 の論点を飛ばしていないか
- 未確定を `decisions.md` / `contract/contract-open-questions.md` に保留 / 仮置きとして登録したか（勝手に確定していないか）
- 出力を過剰生成していないか（MVP は `contract/contract.md` に集約）
- 後続フェーズへ「全部」でなく必要情報だけ抽出して渡したか
- 既存の規約・契約・コード・UI に変更を加えていないか
