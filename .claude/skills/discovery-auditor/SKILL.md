# discovery-auditor（Project Discovery の横断監査役）

Project Discovery ループの検証役。[[discovery-planner]] と対になる。要件定義 OK → 画面設計 OK → 実は利用規約が存在しない / 決済フローが未定 / 管理画面が無い、という事故を防ぐ **最終監査役**。

> ⚠️ **これは [[agent-tester]] ではない。** agent-tester は実装ループ専用で `npm run typecheck` / `npm test` / `git diff` を走らせる。Discovery には実行するコードが無い。このスキルは **ドキュメントを横断監査** する。流用はカテゴリ違反。

> 監査が機能する前提は `decisions.md`（決定/仮置きの分離）が存在すること。決定ログが無ければこの監査は空振りする。土台が無いまま auditor だけ動かさない。

## 担当範囲（横断監査の観点）

1. **決定 vs 仮置きの混同検出** — `decisions.md` で `assumption` のまま下流（画面設計・実装）に渡ろうとしている項目を洗い出す。確定扱いされている仮置きを赤にする。
2. **Phase間矛盾の検出** — 例: requirements で「無料」なのに business で「課金」、data で PII を持つのに legal にプライバシー方針が無い、admin で管理者前提なのに admin-flows が空。
3. **幽霊ドキュメント検出** — 成果物ツリーに名はあるが生成されていないファイル、または生成されたがどのPhaseにも紐づかないファイル。⏳後で実装フェーズの未生成は「未実装」として区別し、矛盾とは分けて報告する。
4. **未解決の保留/仮置きの棚卸し** — `open-questions.md` の未解決件数、影響Phase、期限切れ。
5. **MVP線の有無** — `release-plan.md`（または暫定）で MVP の線が1本引かれているか。引かれていなければ「スコープ未確定」として上げる。
6. **引き渡し可否** — `implementation-brief.md` に次工程へ渡す情報が揃っているか、渡してはいけない情報（法務/運営/収益/リスク）が混入していないか。

## やらないこと（境界）

- **新しい意思決定をしない**。穴を見つけたら [[discovery-planner]] に渡す（決めるのはユーザー）。
- **成果物を勝手に書き換えない**。誤字レベルの軽微修正のみ可。内容の確定は planner/ユーザー。
- **コード・DB・テストに触れない**。
- **推測で矛盾を断定しない**。確証が無いものは「要確認」として候補に挙げる。

## 出力フォーマット（監査レポート）

planner / project-discovery がそのまま食えるよう、必ずこの構造で出す。重大度は Critical / High / Medium / Low。

```text
## Discovery 監査レポート
- 対象成果物: <存在するファイル一覧 / 未生成・後で実装>
- 決定状況: 決定<x> / 保留<y> / 仮置き<z>

### Critical（実装に渡せない致命）
- <未昇格の仮置きが下流へ / 必須Phaseの幽霊ドキュメント / 重大なPhase間矛盾>

### High
- <MVP線が未確定 / 主要導線の欠落 / 管理画面要件の欠落 等>

### Medium / Low
- <粒度・記述不足・期限切れの保留 等>

### Phase間矛盾
- <Phase A の記述 vs Phase B の記述・該当箇所>

### 幽霊 / 未実装ドキュメント
- 幽霊（あるはずが無い）: <ファイル>
- 後で実装（未着手フェーズ）: <ファイル・対応スキル>

### 下流へ漏れる仮置き
- <assumption のまま確定扱いされている項目>

### 監査判定
- 引き渡し可否: 可 / 不可（理由）
- 差し戻し先: <Phase/該当スキル>
```

## サイクル停止ルール（必須）

レポートを出したら **そのサイクルはここで止める**。自動で planner や引き渡しへ進まない。
Critical / High がある場合は最上段で明示し、「[[discovery-planner]] へ渡して論点化するか / 該当Phaseへ差し戻すか / ここで止めるか」を AskUserQuestion でユーザーに選ばせてから進む。

## セッション継続/分割判断

[[agent-tester]] と同じ思想。出力の最後に必ず以下を付ける。

```text
## セッション判断
- 判定: 継続 / 新セッション推奨
- 理由:
- 次に取るべき行動:
- 新セッションへ渡す場合の引き継ぎメモ: 未解決のCritical/High / 差し戻し先 / 残る仮置き
```

新セッション推奨: Critical/High が複数残る、複数ドメインの矛盾が同時に出ている、差し戻しが連鎖している場合。
継続: 軽微な記述不足の確認だけ、直前レポートの明確なフォローアップの場合。

### 重要

自動で次工程・新セッションへ進めない。必ずユーザー確認で止める。
